# 快速上手

从裸板到 HTTP 就绪共 4 步：**构建 → 权重就位 → 启动 → 验证**。

> 前置认知：引擎**只加载自研 VQF v2 单文件**。v1 起不再内置 GGUF / safetensors 加载与
> 引擎内转换，转换职责由随版工具 `vqf_convert/` 承担（见第 2 步）。v0 曾支持直接加载
> safetensors/GGUF，**该路径在 v1 已删除**。

---

## 1) 构建（RK3588 / aarch64 Linux）

```bash
# 板上原生构建（需 gcc + cmake）
./build_rk3588.sh                    # 构建 + 复制到 ./vllm_kestrel
./build_rk3588.sh --run-tests        # 构建 + 运行 PASS/FAIL 自检
./build_rk3588.sh --static           # 全静态（零 .so 依赖）

# 或直接在板上：
cmake -B build-rk3588 && cmake --build build-rk3588 -j8

# x86_64 Linux 主机交叉编译（需要 gcc-aarch64-linux-gnu）
./build_rk3588.sh --cross
```

运行建议 `export OMP_NUM_THREADS=8`（RK3588：4×A76 + 4×A55）。

### 手边没有板子？先用 x86 分支做功能自检

```powershell
# Windows / MinGW-w64（gcc 需在 PATH，或用 -Gcc 显式指定）
powershell -ExecutionPolicy Bypass -File tools\check_x64.ps1
#   → 编译 + 跑 --test-l3 / --test-sparse 自检，退出码 0/1
```

> **x86-64 分支仅用于功能自检与位级一致性对照，不作为性能基准**——x86 上的绝对吞吐
> 与加速比**不可外推到板端**（原因与实测对照见 [构建与复现](https://gitee.com/pei-xiaoguang/kestrel-llm/wikis/构建与复现)）。
>
> ⚠️ **Windows 用户注意**：请把仓库 clone 到**纯 ASCII 路径**。MinGW `ld` 无法处理
> `-o` 参数中的中文路径，`build_x64.ps1` 会以
> `ld.exe: cannot open output file ...: No such file or directory` 失败
> （详见 [构建与复现](https://gitee.com/pei-xiaoguang/kestrel-llm/wikis/构建与复现#已知坑非-ascii-路径会导致-x64-构建失败)）。

## 2) 权重就位

### 2.1 先做转换：safetensors / GGUF → VQF v2

```bash
# 构建转换工具（主机/板端均可；Windows 用 build.bat）
cd vqf_convert && ./build.sh

# 转换（明文）
./vqf_conv --model <safetensors-dir> --convert-vqf <out.vqf> --wmode q4
```

可选（二者可叠加）：

```bash
# 加密（VQF-Enc：SM4-CTR + HMAC-SM3）
VLLM_VQF_KEY='<pass>' ./vqf_conv --model <safetensors-dir> --convert-vqf <out.vqf> --wmode q4

# 内嵌 SM2 供应链签名
VLLM_VQF_SIGN_PRIV='<64hex>' ./vqf_conv --model <safetensors-dir> --convert-vqf <out.vqf> --wmode q4
```

### 2.2 摆放模型目录

模型目录需含 `config.json` + `model.vqf`（VQF v2 单文件，mmap 直挂），以及可选的 `vocab.bin`：

```bash
# vocab.bin 由 tools/build_vocab_bin.py 从 tokenizer.json 生成；
# 缺失时引擎回落到内嵌 vocab，功能可用但体积/词表以模型自带为准
python tools/build_vocab_bin.py <tokenizer.json> <vocab.bin> <vocab.bin>
```

## 3) 启动服务

```bash
# 基础启动：OpenAI 兼容 HTTP 服务（默认端口 8080）
./vllm_kestrel --serve --port 8080 --model <model-dir> --auto-load --wmode q4
```

### 长上下文优化档（全部可选）

```bash
# 注：8K 长上下文基准是 v0 测点，v1 未复测；下列开关为 v1 口径。
# --l3-evict 需配合环境变量 VLLM_L3_PREFIX_REUSE=1，二者共存才有 P3 收益
# （否则 L3 驱逐会静默打掉 prefix-kv，多轮追问将全量重算 prefill）
VLLM_L3_PREFIX_REUSE=1 ./vllm_kestrel --serve --port 8080 --model <model-dir> --auto-load \
    --wmode q4 --sparse-attn --sparse-k 32 --spec --spec-k 4 \
    --l3-evict --l3-ratio 0.75 --l3-min-seq 128 \
    --disk-kv <kv-dir> --threads 8
```

### 大模型省内存档：逐层推理

```bash
# 只支持明文 VQF —— VQF-Enc / 内嵌 SM2 签名的权重会被显式拒绝，必须全层驻留
# 推荐档是 8B（权重常驻 4.19 GB → 0.48 GB，8.7×）；务必用 --threads 4
VLLM_VQF_STREAM=1 ./vllm_kestrel --serve --port 8080 --model <model-dir> --auto-load --wmode q4 --threads 4
```

> **`--threads` 别照抄上例的 8**：RK3588 是 4×A76 + 4×A55，`--threads 8` 会把 4 个 A55 小核
> 拉进 GEMM 并行区——8B 全层 decode 从 186 ms/tok（4 线程）退化到 431 ms/tok（8 线程）。
> 逐层推理的推荐档是 **8B**，一键复现见 `sh tools/bench_value.sh`（详见
> [性能与基准](https://gitee.com/pei-xiaoguang/kestrel-llm/wikis/性能与基准) §4）。

启动日志会打印生效自证，看到 `data=` 远大于 `resident~` 就说明逐层档已生效：

```text
[VQF-STREAM] enabled keep=1 nl=48 segs=11 per-layer=334.1MB data=16847.2MB resident~808.4MB rss=988kB
```

## 4) 验证就绪

```bash
# 健康检查 / 模型列表
curl http://<board>:8080/health
curl http://<board>:8080/v1/models

# 对话（OpenAI 兼容）
curl http://<board>:8080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"qwen3-vl","messages":[{"role":"user","content":"你好"}],"max_tokens":64}'
```

- 管理页 `http://<board>:8080/admin/` 、对话页 `http://<board>:8080/chat/`
  （管理页含「有效优化组合（实测台账）」：8 个组合可一键套用，并标注每项优化针对
  RAM / x86 是否有效；保存配置后需重启引擎生效）。
- **换板或换版本首次运行**：先跑内置自检（`--test-l3` / `--test-sparse` / `--bench-mixed`），
  以自检结果为准。
- 可选 NPU 加速：默认后端为零第三方依赖直驱（自研写 stock rknpu 内核驱动）。首次使用先跑
  板端校准 `./vllm_kestrel --npu --npu-selftest --perf-only`（寄存器命令表未校准通过前，
  提交路径保持禁用并自动回退 CPU）。

## 常见首次失败

| 现象 | 原因与处理 |
|---|---|
| 启动报 VQF 加载失败 | 模型目录缺 `model.vqf`；v1 不再接受 safetensors/GGUF 目录，需先用 `vqf_convert/` 转换 |
| 逐层档被拒绝 | 权重是 VQF-Enc 或内嵌 SM2 签名——逐层推理只支持明文 VQF，须全层驻留 |
| 多轮追问变得极慢 | `--l3-evict` 开了但没设 `VLLM_L3_PREFIX_REUSE=1`，L3 驱逐静默打掉了 prefix-kv |
| `[ATTEST] WARN` | 密钥目录放在 vfat/exfat 上，`chmod` 不生效、私钥变为世界可读；换成 ext4/f2fs |
| Windows 构建 ld 报错 | 仓库路径含中文，改用纯 ASCII 路径或 `-OutDir <ASCII 目录>` |

更多见 [常见问题](https://gitee.com/pei-xiaoguang/kestrel-llm/wikis/常见问题)。
