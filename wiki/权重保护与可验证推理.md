# 权重保护与可验证推理

本页讲清 Kestrel（红隼，工程名 `vllm_kestrel`）的**三道安全防线**及其边界——**加密保密（VQF-Enc 存储态加密）、签名保真（SM2 供应链签名）、出证保实（可验证推理 attestation，schema 3）**。三者层次不同、互不替代，默认均关闭，不影响现有 mmap 加载与推理路径。安全能力只写源文档确证的部分，不夸大为形式化证明或抗攻击能力。

实现位置：`src/model/vqf.c` / `include/model/vqf_format.h` / `src/serve/vllm_attest.c` / `src/common/vllm_crypto.c`。

> 口径：v1.0 板端实测测点 = **2026-09-12**；v0 测点 = 2026-09-05，仅作历史参考，**不得用于 v1 的任何结论**。

## 威胁模型与设计目标

源文档把要回答的问题归纳为三类审计/取证诉求：

| 资产 | 威胁 | 防线 | 机制 |
|---|---|---|---|
| 权重文件（拷走/拔卡/dump eMMC） | 离线破解权重 | **A. 存储态加密** | SM4-CTR 密文落盘 + HMAC-SM3 防篡改 |
| 模型（被替换/投毒/掉包） | 伪模型以假乱真 | **B. 供应链签名** | SM2 对权重明文摘要签名，验签锚定非对称公钥 |
| 推理输出（记录被改/出处伪造/抵赖） | 归档不可信 | **C. 推理出证** | SM3 转录摘要 + SM2 设备签名，逐请求发凭证 |

攻击者能力与对应拦截（源文档 §1.1）：

| 攻击者能力 | 能做什么 | 被哪道防线拦 |
|---|---|---|
| 拿到模型文件（无口令） | 读权重、改字节 | A（密文 + HMAC 认证失败拒绝加载） |
| 持有口令 | 解密、改文件并重算 HMAC | B（无签名私钥无法伪造有效签名） |
| 替换整个模型文件 | 用旧版/投毒权重冒充 | B（`sig.pub`/digest/验签失败拒绝加载） |
| 控制设备（root/内核后门） | 伪造任意响应、偷设备私钥 | C 之外无解（信任根上限） |
| 事后改归档记录 | 篡改请求/输出/时间 | C（验签必失败） |

**设计目标 / 明确不做的事**（源文档 §1.2「诚实起点」）：

- **不做运行时密态计算**：权重解密后驻留 RAM 参与推理，A 是「存储态加密 + 加载解密」，不是全同态/密态推理。
- **不做 ZK/STARK 式「计算本身可验证」**：RK3588 上会产生不可接受的 TTFT 退化；C 做的是工程/司法层面的完整性 + 真实性 + 责任追溯。
- **不解决信任根物理安全**：若攻击者能同时替换引擎二进制（连同内嵌公钥）与模型，B/C 均无法防护。

## 第一道防线：VQF-Enc 存储态加密

**目标**：防模型文件被盗/拷走——落盘即密文，拔卡/dump eMMC 无法恢复可用的量化权重；防篡改——头/目录/数据区任何修改被 HMAC-SM3 认证拦截。明文与密文 VQF 共用同一布局（密文长度 == 明文长度，mmap 直挂布局不变）。

**算法与标准依据**：

| 用途 | 算法 | 标准依据 |
|---|---|---|
| 数据区加密 | SM4-CTR | GB/T 32907-2016 |
| 完整性/认证 | HMAC-SM3 | GB/T 15852.2（RFC 2104 构型） |
| 口令派生 | SM3（单次） | GB/T 32905-2016 |

**密钥来源**：口令经环境变量 `VLLM_VQF_KEY` 传入，经**单次 SM3** 派生 32B 材料，前 16B 作 SM4-CTR 密钥、后 16B 作 HMAC-SM3 密钥（一份口令派生两个独立用途密钥）。`VLLM_VQF_KEY` 未设/为空 → 明文模式（向后兼容）。派生无盐无迭代，弱口令可被离线暴破，生产必须用高熵口令。

**格式标志位**（`include/model/vqf_format.h`）：

- `magic = VQF_MAGIC (0x57465146 "VQFW")`、`version = VQF_VERSION = 2`。
- `flags`：`1<<7 = VQF_FLAG_ENC` 标识加密；`1<<8 = VQF_FLAG_SIGNED` 标识签名。
- `enc_iv[16]` 为 SM4-CTR 初始计数器（偏移 200）。
- 尾部：加密文件为 HMAC-SM3 tag(32B)；明文文件为 FNV-1a checksum(8B)（弱完整性，默认跳过，`VLLM_VQF_CHECK=1` 才校验）。

**加载与校验**：加密文件无口令拒绝加载（`encrypted model requires VLLM_VQF_KEY`）；`file_len + tag_len == 实际文件尺寸` 兜底防截断/拼接；随后**单遍 HMAC 认证 + 原位解密**（`mprotect` 使 mmap 可写、`MAP_PRIVATE` COW，磁盘密文不变），tag 不一致报 `HMAC-SM3 mismatch (tampered or wrong key)` 并拒绝。篡改头部（arch/flags/enc_iv 等）、目录区或数据区任字节均导致 tag 校验失败。

**边界**：加密加载为一次性全量解密 + HMAC 校验，明文 VQF 实测加载 ≈1.27~1.29 s，加密 VQF ≈92.3~92.5 s（推理阶段不再重复承担）。**加密权重必须全层驻留**——逐层推理 `VLLM_VQF_STREAM` 会显式拒绝加密文件。

## 第二道防线：SM2 供应链签名

**补的是 HMAC 的短板**：HMAC 能防「不知道口令的人改文件」，但**持有口令的人仍可替换整个模型并重算 HMAC**；SM2 把「模型确实出自发布方」锚定在非对称私钥上。不做运行时逐 token 验签，验签是一次性加载期动作。

**签名对象**：模型权重本身（明文逻辑内容的摘要 D），不是某个加密实例：

```text
D = SM3( header_canonical ‖ directory ‖ plaintext_data )
header_canonical = VQFHeader 中 flags 含 VQF_FLAG_SIGNED、file_len=0、sig 块全 0 的头
```

签明文摘要 D 的好处：**签名一次、任意口令加密**，A 与 B 完全正交——口令泄露（A 失效）不连坐 B；攻击者即使拿到口令可解密，也没有签名私钥，无法伪造一份有效签名去替换模型。

**私钥来源**：发布方离线持有 SM2 私钥 `d`，只进入离线转换/签名工具（`VLLM_VQF_SIGN_PRIV`，64 hex），**不进入设备**；设备只存公钥 `P`（64B），运行时经 `VLLM_VQF_SIGN_PUB` 注入或**编译期内嵌**（`VLLM_SM2_PUB_HEX`）。文件内 `sig.pub` 只作诊断，**验签必须用内嵌/注入的可信公钥**；无信任公钥时对签名模型 fail-closed。

**验签时机**：加载期（`vqf_load`），`do_verify = signed && (enc || VLLM_VQF_VERIFY=1)`。流程：读 header 判 `VQF_FLAG_SIGNED` → （加密时随解密同单遍）算 D → 与 `header.sig.digest` 快速自检（不等直接拒绝，省一次 ECC）→ `vc_sm2_verify(P_trusted, D, 32, VQF_SM2_ID, r, s)`，失败报 `[VQF] SM2 verify failed (model replaced/tampered)` → 交叉校验 `header.sig.pub == P_trusted`，不一致报 `[VQF] SM2 pub mismatch`。VQF 签名的签名 ID 约定 `VQF_SM2_ID = "vllm-kestrel-vqf"`。

**性能**：加密码型验签与解密合并为单遍，仅增 SM3 计算（可忽略）；明文模型验签**强制全量读**数据区，抵消 mmap 懒加载收益，故默认关、需 `VLLM_VQF_VERIFY=1` 显式开启。SM2 验签本身约几十 ms。

## 第三道防线：可验证推理 attestation

**核心原理**：每次推理响应打一张「数字凭证」= **SM3 转录摘要 + SM2 设备签名**。安全模型是「签名设备可信、设备私钥不泄露」；验证方只需保留请求原文、输出文本、凭证 JSON、设备公钥即可离线复算验签。

**schema 版本**：`schema=3`，帧 magic `"VLLM-AT-3"`（旧 schema=2 凭证按 `"VLLM-AT-2"` 复算，两版帧布局相同）。摘要绑定字段：

```text
digest = SM3( "VLLM-AT-3"
           || F(model_fp) || F(model_id) || F(device_id) || F(user) || F(params)
           || F(n_prompt_tokens) || F(n_gen_tokens) || F(finish) || F(ts)
           || F(body_sha) || F(output_text) )
// F(x) = u32be(len(x)) || x
```

其中 `body_sha = SM3(客户端原始请求体)`（含多模态 base64 图片 URL），**绑定设备实际收到的那一坨字节**——取证方对自己保存的请求原文做一次 SM3 即可逐字节比对，无需 tokenizer、无需重建聊天模板。签名用 SM2（`ID = "VLLM-ATTEST-1"`，消息 = 32B digest，输出 `r||s`）。

**凭证内容**：非流式响应 JSON 增顶层字段 `"attest"`；流式在 SSE 末尾发独立事件 `chat.completion.attest`。凭证含 `schema / algo("SM2-SM3") / ts / model / model_fp / device / user / params / prompt_tokens / n_tokens / finish / body_sha / digest / signature`。

**覆盖路径**：`/v1/chat/completions`（非流式/流式）与 `/v1/completions`（非流式）已覆盖；Anthropic 兼容 `/v1/messages` **暂不出证**（V1 边界）。`model_fp` 锚定「目录 + config + 文件尺寸」层；若模型是**签名 VQF**（B 开启并验签通过），权重级信任由 B 提供，两链闭合。

**验签方式（离线零依赖）**：`tools/verify_attest.py` 为**纯 Python 零依赖**实现（SM3 + SM2 验签 + digest 复算），`--selftest` 可自检脚本自身实现。归档需字节精确（勿转码/勿加 BOM）：请求原文 `req.json`、响应文本 `out.txt`（非流式 `content` / 流式各 `delta.content` 拼接）、凭证 `proof.json`（`attest` 对象）、设备公钥 `vllm_attest.pub`（128-hex 单行）。README 能力对照表另载明 v1 支持「浏览器内 / 离线零依赖验签」。

## 使用方式

> 以下命令、环境变量、工具名均取自源文件，逐条核对无误。

**① 离线：一次转换，加密 + 签名就位**

```bash
# 生成供应链签名密钥对（防线 B，私钥留离线机）
./vllm_vqf_sign --genkey
# 一次转换同时完成加密（防线 A）+ 内嵌签名（防线 B）
# 转换工具 vqf_convert/：先 ./build.sh（Windows: build.bat）得到 vqf_conv
VLLM_VQF_KEY='<高熵口令>' VLLM_VQF_SIGN_PRIV='<privhex>' \
  ./vqf_conv --model <safetensors-dir> --convert-vqf model.vqf --wmode q4
```

离线补签 / 密钥 / 验签工具 `vllm_vqf_sign`：

```bash
./vllm_vqf_sign --genkey          # 生成 SM2 密钥对（d / P）
./vllm_vqf_sign --pub <d_hex>     # 导出公钥 hex
./vllm_vqf_sign --sign <d_hex> --in <file> --out <sig>   # 离线对摘要签名（排障用）
./vllm_vqf_sign --verify <p_hex> --in <file> --sig <sig> # 验签（排障用）
```

**② 设备部署（RK3588）**

```bash
# 防线 A+B：加载加密签名 VQF（验签默认随解密开启）
VLLM_VQF_KEY='<高熵口令>' VLLM_VQF_SIGN_PUB='<pubhex 128hex>' \
  ./vllm_kestrel --serve --model <dir> --wmode q4
#    · 明文模型也想验签（防线 B）：加 VLLM_VQF_VERIFY=1（强制全量读）
#    · 编译期固公钥：构建时 -DVLLM_SM2_PUB_HEX="..."，运行时免注入
# 防线 C：追加 VLLM_ATTEST=1 VLLM_ATTEST_DIR=./.attest（私钥首次自动生成）
```

**③ 出证与离线验证（防线 C）**

```bash
# 启动（出证 + 自检门 + 逐请求 PASS/FAIL 日志）
VLLM_ATTEST=1 VLLM_ATTEST_DIR=./.attest VLLM_ATTEST_SELFTEST=1 VLLM_ATTEST_LOG=1 \
  nohup ./vllm_kestrel --serve --model <model-dir> --auto-load --port 8090 > /tmp/att.log 2>&1 &

# 验证方离线一键验签
python tools/verify_attest.py --proof proof.json --request req.json \
    --output out.txt --pub vllm_attest.pub
python tools/verify_attest.py --selftest   # 验证脚本自身 SM3/SM2 实现自检
```

**关键环境变量汇总**：

| 变量 | 防线 | 作用 |
|---|---|---|
| `VLLM_VQF_KEY` | A | 口令：转换时加密产出 VQF-Enc；加载时解密并认证 |
| `VLLM_VQF_SIGN_PRIV` | B | 64 hex 私钥，转换时内嵌 SM2 签名（离线） |
| `VLLM_VQF_SIGN_PUB` | B | 128 hex 可信公钥，设备侧验签（优先于编译期内嵌） |
| `VLLM_SM2_PUB_HEX` | B | 编译期内嵌可信公钥（兜底） |
| `VLLM_VQF_VERIFY` | B | `1` 对明文模型也验签（强制全量读） |
| `VLLM_VQF_CHECK` | A | `1` 校验明文文件的 FNV-1a checksum |
| `VLLM_ATTEST` | C | `1` 开启出证；缺省/`0` 关闭 |
| `VLLM_ATTEST_DIR` | C | 密钥目录（缺省 `.`），含 `vllm_attest.priv`(0600)/`vllm_attest.pub` |
| `VLLM_ATTEST_SELFTEST` | C | `1` 启动跑 PASS/FAIL 自检门 |
| `VLLM_ATTEST_LOG` | C | `1` 每次出证打 `[ATTEST] seal digest=... verify=PASS` |
| `VLLM_ATTEST_DUMP` | C | `1` 打完整预映像 hex（排障用，勿常开） |

## 边界与已知限制

- **口令派生弱**：单次 SM3，无盐无迭代（非 PBKDF2/Argon2）；口令熵即密钥熵，弱口令可被离线字典/暴力攻击。口令经环境变量传递，运行期可经 `/proc/<pid>/environ` 被同权限进程读取；**不具备硬件级密钥隔离**（TEE/安全芯片）。
- **IV 非密码学随机**：VQF-Enc 的 IV 来源为 xorshift128（种子取 time+地址），仅提供**每文件唯一性**（混淆级）；同一口令下两文件 IV 碰撞则密钥流复用。对比：SM2 签名 `k` 由 `getrandom` 提供，属密码学安全。
- **加密权重必须全层驻留**：`VLLM_VQF_STREAM` 会显式拒绝加密文件；加密/签名 VQF 加载需全层驻留（全量路径与 `--stream` 路径均支持加密/签名，但逐层驻留不适用）。
- **明文模型验签抵消 mmap 收益**：签名验证强制全量读数据区（数 GB）。建议签名模型默认走加密；明文模型验签用 `VLLM_VQF_VERIFY=1` 显式开启。
- **私钥文件保护依赖 OS 权限**：设备私钥 `vllm_attest.priv` 依赖 `0600` + 目录 ACL，生产建议 TEE/HSM 或受控分区；B 的私钥 `d` 只在离线签名工具中出现。
- **信任根是安全上限**：攻击者若能同时替换引擎二进制（连同内嵌公钥/设备私钥）并用自家密钥重签/重出证，SM2 无法防护——依赖固件/二进制完整性（安全启动、签名固件、写保护）。
- **出证能证明 / 不能证明**：能——记录完整性、真实来源、模型归属（`model_fp` 钉住目录/config/尺寸）、弱防重放（`ts` 入摘要）。不能——❌ 语义正确性（验签通过 ≠ 结论正确）；❌ 计算真实发生（签名是设备/机构**声明**，非密码学证明计算过程）；❌ 推理可复现（`temperature>0` 不可复现）；❌ 强时间公证（`ts` 取设备本地时钟）；❌ 绝对权重防伪（`model_fp` 只盖 config.json + 目录 name:size，**同字节数换权重可绕过**，根治 = 防线 B）。
- **覆盖缺口**：Anthropic `/v1/messages` 暂不出证；batch 跨请求并发放大内存；验证方须字节精确保存请求/输出/凭证，并安全核对公钥。

## v0 / v1 差异

以 README 能力对照表为准：

| 能力 | v0（上一公开版本） | **v1.0（本版本）** |
|---|---|---|
| 安全与合规 | VQF 存储态加密（SM4-CTR + HMAC-SM3）、SM2 供应链签名 | **追加可验证推理 attestation（schema 3，含请求原文绑定）**，浏览器内 / 离线零依赖验签 |

v1.0 在此块新增/修复的具体项（README「v1.0 变更摘要」）：

- **attestation schema 3**：新增**请求原文绑定**（`body_sha = SM3(客户端原始请求体)`），只改 `top_k` / `thinking` 也必须改摘要。
- **转换工具支持加密 / 签名产出**：`vqf_convert/` 设 `VLLM_VQF_KEY` 即输出 VQF-Enc 加密文件（SM4-CTR + HMAC-SM3），设 `VLLM_VQF_SIGN_PRIV` 即内嵌 SM2 供应链签名，二者可叠加。
- **VQF 离线补签口径修复**：离线签名工具先置 `VQF_FLAG_SIGNED` 再算摘要（与写侧口径一致），修复补签后永远 digest mismatch 的问题。
