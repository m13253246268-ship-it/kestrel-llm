# 架构总览

本页是 Kestrel（红隼，工程名 vllm_kestrel）的导航型总览：把散落在《技术文档》各章的架构信息压成一张全局图景，并标出每个子系统该去哪个 Wiki 页面看细节。

Kestrel 是一个面向 **aarch64（ARMv8.2-A + dotprod/fp16）CPU** 的边缘 LLM 推理引擎，开发与基准平台为 RK3588（4×A76 + 4×A55），纯 C11，产物是单可执行文件 `vllm_kestrel`。范围上它只针对 **Qwen3-VL 系列（2B/8B，含视觉塔多模态）与 Qwen3-MoE 系列（文本）** 开发并实测，tokenizer/mrope/视觉塔均为 Qwen3-VL 特化实现，不构成通用引擎。

> 口径提示：标注 `（v0 测点）` 的数字取自旧版加载逻辑，不得用于 v1 的任何结论；未标注的 v1 板端实测测点为 **2026-09-12**。本页只做架构导航，性能数字请以 [性能与基准](https://gitee.com/pei-xiaoguang/kestrel-llm/wikis/性能与基准) 为准。

## 引擎定位与总体分层

引擎定位「边缘单机推理」：单一 SSE 流服务、串行推理队列、可选 NPU 透明卸载。源码按职责分为四层，外加一个可选卸载层：

| 层 | 源码目录 | 职责 |
|---|---|---|
| 服务层 | `src/serve/` | HTTP/SSE、路由、连续批处理、管理 API、可验证推理出证、内嵌 HTML |
| 模型层 | `src/model/` | 权重加载/量化与**引擎推理内核**、VQF v2 读写、Qwen tokenizer/mrope、视觉塔 |
| 内核层 | `src/core/` | 自研线程池、L3 磁盘 KV；另含随二进制编译的同树 SHS fp32 参考研究栈 |
| 公共/平台层 | `src/common/` | 国密原语（SM3/SM4-CTR/HMAC-SM3/SM2）、设备画像与权重适配档 |
| 可选卸载层 | `src/npu/`、`src/media/` | NPU 透明卸载；H.264 解码（`media/`，默认构建不启用） |

安全（存储态加密 / 供应链签名 / 出证）不是独立一层，而是横切服务层与公共层，详见 [权重保护与可验证推理](https://gitee.com/pei-xiaoguang/kestrel-llm/wikis/权重保护与可验证推理)。

## 目录与模块职责

编译单元见 `CMakeLists.txt`：共 **28 个 C 源文件**（main.c + core 11 + common 2 + serve 6 + model 6 + npu 2），C11，单可执行文件 `vllm_kestrel`；`media/` 的 `vllm_mp4.c` / `h264_dec.c` 不在默认构建。

| 源码路径 | 职责 |
|---|---|
| `src/main.c` | 入口：参数解析、模型加载、serve/工具模式分发 |
| `src/common/vllm_crypto.c` | 国密原语 SM3 / SM4-CTR / HMAC-SM3 / SM2（KAT 红线） |
| `src/common/vllm_device.c` | 设备画像与权重适配档（RK3588/x86 白名单） |
| `src/core/vllm_tp.c` | 自研线程池（引擎使用，替换 OpenMP，API 1:1 镜像） |
| `src/core/vllm_l3.c` | L3 冷块 Q4 落盘（磁盘格式 / evict 内核） |
| `src/core/vllm_superpos.c`、`vllm_scheduler.c`、`vllm_attention.c`、`vllm_transformer.c`、`vllm_tokenizer.c`、`vllm_matmul.c` | 同树 SHS fp32 参考研究栈（superposition 算子、批调度、paged 注意力、LLaMA 风格参考解码器、词级分词器、`vmm_*` 工具）；引擎 Qwen 热路径不使用 |
| `src/model/vllm_safetensors.c` | 权重加载/量化 + **引擎推理内核**（Q8/Q4 各布局 GEMM、稀疏/flash 注意力、prefill/decode 主路径；含 llama.cpp 衍生 4x4 asm 复刻） |
| `src/model/vqf.c` | VQF v2 读写（mmap 直挂；SM4-CTR 加密 + HMAC + SM2 签名） |
| `src/model/vllm_tokenizer_qwen.c` | Qwen tokenizer（含 mrope） |
| `src/model/vllm_vision.c` | Qwen3-VL 视觉塔编码（ViT） |
| `src/model/vllm_media.c` | 图片解码（stb_image）/ 视频帧 |
| `src/serve/vllm_http.c` | 最小 HTTP 服务器（select 轮询 + SSE） |
| `src/serve/vllm_server.c` | 路由、对话/补全处理、多模态 prompt 构建、出证集成 |
| `src/serve/vllm_batch.c` | 连续批处理线程 |
| `src/serve/vllm_admin.c` | `/admin` 管理 API（状态/配置/模型加载） |
| `src/serve/vllm_attest.c` | 可验证推理（SM3 摘要 + SM2 设备签名，schema=3） |
| `src/serve/embedded_web.c` | 内嵌 HTML（由 `tools/build/gen_embedded_web.py` 生成） |
| `src/npu/vllm_npu.c`、`src/npu/rk3588/vllm_npu_direct.c` | NPU 透明卸载统一接口；零依赖直写 rknpu 内核驱动 |

> `core/` 内另有 `vllm_ckks` / `vllm_fhe` / `vllm_ntt`：RNS-CKKS 全同态推理研究内核，与明文引擎共存，`--fhe-test` 覆盖其自检，不属于本文档范围。

## 一次推理请求的数据通路

摘自《技术文档》§2.3，完整链路如下：

```text
HTTP 请求
  → vllm_server 路由
    → 文本：qwen_tokenizer_encode → run_completion
         ├─ 前缀复用判定（内存 last_ids LCP / disk-kv LCP）
         ├─ prefill（st_qwen_model_prefill_batch，GEMM + 注意力）
         └─ decode 循环（逐 token，采样 / 推测解码）
    → 多模态：build_multimodal_prompt
         ├─ image_url    → 图片解码 → 视觉缓存命中? → 回放 : st_vision_encode_image
         ├─ video_frames → 帧解码 → st_vision_encode_video
         └─ vision_tokens→ 客户端预处理特征直接注入（跳过 ViT）
         └─ 拼接文本/视觉 token → run_multimodal_completion
  → SSE / JSON 响应
```

关键约束：HTTP 层由 `--threads`（默认 8）个 worker 处理并发连接，但**推理本身串行**（单一 SSE 流）；`vllm_http.c` 同一时刻只服务一个流式请求，因此路由处理无需加锁（路由层自身有锁）。

## 关键自研组件落在哪一层

| 自研组件 | 位置 | 说明 |
|---|---|---|
| 手写 NEON 量化 GEMM/GEMV | 模型层 `src/model/vllm_safetensors.c` | Q8 8x8 tiled（`vdotq_s32` SDOT INT8 点积）、Q4 4x4 nibble、8x8l decode 副本；`core/vllm_matmul.c` 的 `vmm_*` 只是同树 fp32 参考栈 |
| 自研线程池 `vllm_tp` | 内核层 `src/core/vllm_tp.c` | 替换 OpenMP：持久工作线程 + 调用线程参与，静态连续 chunk，创建时绑定物理核；API 与所用 OpenMP 面 1:1 镜像（`vllm_tp_parfor / parcall / worker_id / threads / init / wtime`） |
| 自研国密 | 公共层 `src/common/vllm_crypto.c` | SM3 / SM4-CTR / HMAC-SM3 / SM2，服务于 VQF 加密、签名与出证 |
| 自研权重格式 VQF v2 | 模型层 `src/model/vqf.c` + `include/model/vqf_format.h` | 把「量化 + 布局 repack」固化到文件，加载 = mmap + 元数据校验 + 指针直挂；离线转换在独立工具 `vqf_convert/` |

## 体积与零依赖边界

- 单产物约 **0.8 MB**，零第三方运行时依赖（v1 口径）。
- 标准（动态）构建需 gcc + cmake，链接 `-lm`；OpenMP（`-fopenmp`）仅用于 NPU direct 后端的 pack 并行，引擎核心走自研 `vllm_tp`。
- 全静态构建（`-DVLLM_STATIC=ON` → `-static`）：`file` 报 `statically linked`、`ldd` 报 `not a dynamic executable`、`readelf -d` 无 NEEDED；glibc/libm/libgomp 全部内联，体积 1.5MB（vs 动态 0.69MB）。静态 glibc 下 NPU rknn 后端（dlopen）运行时加载失败回退 CPU，NPU direct 后端不受影响。
- 例外（照实写）：仓库仍带第三方单头文件 `src/model/stb_image.h`（图片解码），随源码编译；4x4 asm 内核为 llama.cpp 衍生复刻（`tools/kernels/llama_gemm_q4_0_4x4_asm.c` / `extract_llama_asm.py`）。

## v1 的架构级变更

- **纯 VQF 运行时**：只认自研 **VQF v2**（`VQF_VERSION=2`）单文件，加载为 mmap 指针直挂；内置 GGUF/safetensors 加载与引擎内转换（`vllm_gguf.c`、`convert.html`）已删除，相关 CLI（`--convert-vqf` / `--convert-gguf` / `--gguf-info`）一并移除。
- **转换职责外移**：由随版发布的独立工具 `vqf_convert/`（产物 `vqf_conv`）完成，与引擎 serve 使用完全相同的加载/量化/repack 序列，产物与引擎**逐字节一致**。转换页细节见 [权重保护与可验证推理](https://gitee.com/pei-xiaoguang/kestrel-llm/wikis/权重保护与可验证推理)。
- **逐层推理（VLLM_VQF_STREAM）**：分层驻留，让权重常驻 RSS 与模型体积/层数解耦；**只对明文 VQF 生效**，VQF-Enc / 内嵌 SM2 签名的权重被显式拒绝，须全层驻留。细节见 [逐层推理与 KV 缓存](https://gitee.com/pei-xiaoguang/kestrel-llm/wikis/逐层推理与KV缓存)。
- **KV v2 惰性分配 + L3 分层驻留 + P3**（L3 驱逐 × 前缀复用共存，`VLLM_L3_PREFIX_REUSE=1`）。
- **可验证推理 attestation schema=3**（新增 `body_sha` 请求原文绑定，magic `VLLM-AT-3`，兼容验 schema=2 旧凭证）。
- **x86-64 移植层随版**（`tools/build/build_x64.ps1` / `tools/build/check_x64.ps1`），仅用于功能自检与位级一致性对照，**不作性能基准**。

## 位级确定性

引擎数值路径（GEMM / attention / softmax / 采样）完全确定：同输入同参数输出逐位一致（多线程 40/40 一致实测，2026-08-29 修复 attention 尾部数据竞争）。注意事项：

- 默认前缀复用属正常（复用路径与全量重算的舍入顺序不同）；严格复现加 `--no-prefix-kv`。
- `spec / prefix-kv / disk-kv` 在验证场景下输出与全量逐字节一致。
- `batch`（`--batch-max`）跨 prompt 存在 near-tie 双内核翻转风险，**非普遍保证**。
- 逐层推理的驱逐只丢弃干净文件页，内容由文件重建，`--stream-test` 的贪心 TOKIDS 序列在全层/逐层两档下逐位一致。
