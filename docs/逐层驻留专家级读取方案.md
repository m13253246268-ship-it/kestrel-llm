# 逐层驻留「专家级权重读取」方案（形态 A）设计稿

> 状态：**已实现（默认关）+ 板端判否 + 已收口**（2026-09-25）。
> **收口宣告**：形态 A 家族（A1/A1E/A2）冻结为**可选档（默认关）**，**不再继续实现或测量**；
> 唯一开放项 = 上游 [PRE_REG_STREAM_EXPERT_GRAIN_PROBE.txt](PRE_REG_STREAM_EXPERT_GRAIN_PROBE.txt)
> 的 **P-EW-1 / P-EW-2** 与 [PRE_REG_STREAM_SA.txt](PRE_REG_STREAM_SA.txt) 的 **P-A-1**——
> 三者都只能在 **N1（页表主导端）** 采集，而 N1 通道当前不可达。
> 账目与逐条证据见 §10，收口账见 [PRE_REG_STREAM_SA.txt](PRE_REG_STREAM_SA.txt) §9。
> **在拿到 N1 判据前不得转正为默认**；也不得在板端继续做**不可裁决**的测量（板端已自证无该轴灵敏度）。
>
> 已实现（`VLLM_SA` / `VLLM_SA_DOWN` / `VLLM_SA_STAT` / `VLLM_SA_EVL`，全部默认关）与已验的五层见 §10。
>
> 已冻结的前置决策（用户）：down 采用 **D1**（层入口整层 DONTNEED、取消整层 WILLNEED）；
> **接受 down 的 ≈2.4× 页共享地板**（单专家 ≈3.37×、top-8 并集 ≈2.37×），
> 不为此改 VQF 文件布局。

---

## 0. 一句话方案

把逐层驻留档（`VLLM_VQF_STREAM`）下**专家段**（`q4/q8_gate/up/down`）的驱逐/预取，从
「每 token 对**整层**（含全部 128 专家）发 WILLNEED + DONTNEED」，改成
「按**每层实际驻留集 R_l** 收敛到**本 token 激活集 A_l**（top-8）的专家级操作」；
非专家段（attn/norm）保持现状整层；down 因页共享与列带 < 页粒度，单独定策略。
目标：让每 token 的 madvise 区间与**本 token 激活的 8 个专家段**（13.5 MiB/层量级）同量级，
而不是与**整层**（334.1 MiB/层）同量级。

> 口径提醒：现状「整层 × (WILLNEED+DONTNEED)」合计 ≈ **31.32 GiB/token**（约 2× 全模型体积）；
> 本方案的比较对象是**整层 vs 激活段**，不是「全模型体积」。

## 1. 问题定义（代码事实 + 量化）

### 1.1 两轴现状

| 轴 | 现状 | 位置 |
|---|---|---|
| 计算 | 稀疏：decode 只算 top_k=8 个专家 | [`st_moe_ffn_sparse_q4`](../src/model/vllm_safetensors.c#L12893) 选路后只遍历 `sel[0..tk-1]`（[L13068-L13150](../src/model/vllm_safetensors.c#L13068-L13150)） |
| 驻留/读取 | **整层**：seg 的 `step = bytes/nl` 对 `q4_gate/up/down` 含全部 128 专家 | [`vqf_stream_setup`](../src/model/vqf.c#L676-L755)；层入口整层 DONTNEED(l-keep) + 整层 WILLNEED(l+1)（[`vqf_stream_layer_advance`](../src/model/vqf.c#L1058-L1109)） |

### 1.2 代价量化（N1/aarch64，30B-A3B-q4，t32，页缓存热）

- 实测 `stream − full` = **+277.5 ms/token**（[MANIFEST §3.2](../docs/bench/20260925-n1-moe-30b-a3b/MANIFEST.txt)）；
  该 Δ 在 T=32/40/48/56/64 上为 277.5/281.0/293.0/292.0/306.5，几乎不随算力变
- 现档每 token madvise 区间 = `334.1 MiB × 48 × 2(WILLNEED+DONTNEED) = 32,073.6 MiB`
  = **31.32 GiB（≈33.63 GB）≈ 8.21M 页** ⇒ `277.5 ms / 8.21M = ` **33.8 ns/页**
- **W 与 D 的贡献拆分未知**：由 L1（只 DONTNEED）/ L2（只 WILLNEED）探针裁决，本设计不预设
- **旁证（跨 regime，不作判据）**：板端 v1.0 `--stream-test` **冷页缓存**下
  （[性能与基准.md L44-L49](../wiki/性能与基准.md)），8B（稠密，每 token
  读满 6.60GB）Δ=+157ms、30B-A3B（激活 ~1.6GB）Δ=+398ms；比值 2.54 ≈ 模型字节比 2.68，
  而 ≠ 激活字节比 0.24 ⇒ **提示**「开销 ∝ 整层区间字节，不 ∝ 激活权重」。
  （N1 侧为热页缓存，两 regime 不可混引；此反证只用于提出机制假设，判据一律取 N1 的 L0–L4）

### 1.3 每层字节分解（30B-A3B，`per-layer=334.1MiB`，日志口径）

| 段 | 每层 | 占比 | 每层页数（4096B） |
|---|---|---|---|
| `q4_gate` + `q4_up` | 216.0 MiB | **64.7%** | 55,296 |
| `q4_down` | 108.0 MiB | **32.3%** | 27,648 |
| attn/norm 等非专家段 | 10.1 MiB | 3.0% | ≈2,586 |
| 合计 | 334.1 MiB | 100% | ≈85,530 |

⇒ 按字节占比线性外推：只收窄 gate/up 最多省到 35.3%（**刚好卡在 P-EW-1 的 0.35 阈值之外**）；
**down 必须一并处理**才可能达标。这是本方案必须给 down 单独定策略的原因。

## 2. 设计目标与不可动约束

**目标**
1. 每 token 的专家段 madvise 区间与 `|A_l|`（=8）同量级，而不是与 `ne`（=128）同量级。
2. **RSS 有界**：默认档必须在 15.6GiB 板端可跑（30B 场景）。
3. 不改动非专家段（attn/norm）的现状语义，保住跨层 I/O 重叠。

**不可动（红线）**
- **A≡C**：只动 PTE/页缓存（`madvise`/`posix_fadvise`），**不触碰任何浮点求和顺序**；
  判据 = 与 full 档 TOKIDS 逐位相同。
- 仅**明文 VQF**；加密档继续被 `vqf_stream_setup` 拒绝（[L680-L685](../src/model/vqf.c#L680-L685)）。
- **不新增第三条轨**：`VLLM_EW*` 保持原型不动（EW 激活时优先接管）；不改 `VLLM_DN_D2` 语义。
- 不减少每 token 的**读取总量**，只减少 madvise 区间与页表重建量（诚实边界，
  [vqf.h L64-65](../include/model/vqf.h)）。对外表述不得写成「减少了读取量」。

## 3. 核心机制

### 3.1 关键洞察：区间必须相对「驻留集」，而不是「层的全体」

这是本方案与 EW（静态热窗）原型的区别所在：

- **参照系错误（= EW 原型的做法）**：层入口驱逐「本层**全体非热**专家段」。H=8 时驱逐量
  `(128−8)/128 × (gate+up) + down = 202.5 + 108 = 310.5 MiB/层`（仅 DONTNEED）——
  它虽小于现状的「整层 W+D = 668.2 MiB/层」，但相对「激活 8 专家段」仍是 **23 倍**量级：
  参照系还是「层的全体专家」，「保留 8 个」在页粒度上等于几乎没保留。
- **口径诚实说明**：归档对 EW 只记「`VLLM_EW*` 源文件**未给收益数字**」
  （[优化配置与边界.md L28](../wiki/优化配置与边界.md)），**并未给出「实测零收益」**。
  因此「EW 无效」在本方案中是**待证假设**（其区间是现状的一半量级，按「成本 ∝ 区间」的假设
  本应有可观收益）；该假设与本节机制主张一起，由 L1/L2/L3 探针（W/D 拆分 + 区间→0 地板）
  裁决。**本设计不依赖该假设成立。**
- **正确做法**：驱逐的参照系是**当前实际驻留集 R_l**。只要策略保证「每次进入层 l 后，
  R_l 被收敛到 A_l（8 个）」，那么：
  - 首次进入（R=∅）⇒ 区间 0；
  - 稳态 ⇒ 区间 = `|A_{l,t-1} \ A_{l,t}| ≤ 8` 个专家段，与 `ne` 无关。
  ⇒ **区间从 128 专家的量级降到 8 专家的量级**，且**不依赖跨 token 专家复用率**
  （复用率只影响这 8 个里有多少需要重读）。

### 3.2 记账结构

```c
/* vqf.c：形态 A 每层驻留专家记账（A_l 的收敛记账，非精确驻留表） */
#define VQF_SA_MAXLAYER 256
static struct {
    int      active;          /* VLLM_SA=1 启用（默认关） */
    int      down_mode;       /* 0=WHOLE（默认，RSS 有界） 1=KEEP（down 不驱逐） */
    uint8_t *res;             /* nl × ceil(ne/8) 字节；bit=1：认为该专家段驻留 */
    int      nl, ne;
} g_sa;
```

- 内存：`256 × 16B = 4KB`，可忽略。
- **语义是"记账"不是"真相"**：真实驻留可能更多（页被邻专家共享等）。
  误判方向必须保守 —— 见 §6.2。

### 3.3 时序：把专家段的驱逐/预取从「层入口」移到「选路后」

| 时机 | 现状 | 形态 A |
|---|---|---|
| 层入口（先于本层权重读取） | 整层 DONTNEED(l-keep) + 整层 WILLNEED(l+1) | **只处理非专家段**（保持现状语义，保住跨层重叠）；down 按 §3.4 策略处理 |
| 选路后（top-k 已定） | `vqf_ffn_prefetch`：仅当 `VLLM_EW_PREFETCH=1` 时对 `sel[]` 的 gate/up 发 WILLNEED | **专家段在此收敛**：先驱逐 `R_l \ A_l`，再 `R_l := A_l`，再对 `A_l` 发 WILLNEED |

选路后时机的必要性：只有此时才知道**本 token 的真实 A_l**。
若沿用层入口时机，保留集只能取「上一 token 的 A_l」，驱逐量退化为 `ne − |A|`（≈整层），
又回到 §3.1 的错误做法。

代价：专家段预取失去跨层 I/O 重叠（现状 WILLNEED(l+1) 与本层计算重叠）。
gate/up 的激活段仅 13.5 MiB/层，N1 上属页表成本；板端 eMMC 上需实测（§7 的 P-A-3）。

### 3.4 down 的特殊性（本方案的硬缺口）

几何（代码事实，[`rdp_dn_worker` L12834-L12849](../src/model/vllm_safetensors.c#L12834-L12849)）：

- down 张量 `rows=d`、`cols=ff`，q4 4×4 tiled：**行组字节 = (ff/32)×72 = 221184B（54 页）**，
  连续堆放 `d/4 = 512` 个行组；
- 专家 e 在**每个行组内**的列带 = `[(e·ef/32)·72, +24×72)` = **1728 B**；
- 4 KB 页跨 ≈ 2.37 个专家带 ⇒ **页被邻专家共享**；专家带不被页边界整除。

推论：
1. **单专家带过取 ≈3.37×；top-8 并集地板 ≈2.37×**（几何估计值；源码他处记「约 3.4×」，
   见 [vqf.c L1131-L1134](../src/model/vqf.c)）——已决策接受。
2. **「保留 8 个专家、驱逐其余 120 个」在 down 上不可表达**：保留集在文件上散布为
   `512 行组 × 8 段 = 4096` 个小段，驱逐补集需要 ~4000+ 次 syscall/层
   （48 层 ≈ 20 万次/token，按 ~1.5µs/次 ≈ 300ms，**不可接受**）。
3. 因此 down 只有三种可行形态，**必须显式选一个**：

| 选项 | down 的动作 | 每 token 页数（48 层） | Δ 贡献 | RSS 增量 | 结论 |
|---|---|---|---|---|---|
| **D1 `WHOLE`（默认推荐）** | 层入口**整层 DONTNEED**（保持现状区间），**取消整层 WILLNEED**，靠计算按需缺页 | 1.33M | ≈ +44.8 ms | **0** | 保 RSS 有界，Δ 仍达标（§4） |
| **D2 `KEEP`** | **完全不驱逐也不预取**（首次 fault 后常驻） | 0 | 0 | **+5.06 GiB（5.44 GB）** | 最优延迟，但吃掉板端余量；须用户显式开启 |
| D3 文件重排 | 转换期把 down 改为专家-major（每专家 884736B 连续、216 页对齐） | 161K | ≈ +5.4 ms | 0 | **格式级改动，另立项**（预注册 §4(h)）；`VLLM_DN_D2` 是匿名 repack（同等 +5.06 GiB、不可回收），不可替代 |

> D1 的「取消 down 的 WILLNEED」是纯收益：现状对 down 整层预读本就是过取
> （[vqf.c L1131-L1134](../src/model/vqf.c) 原文：「约 3.4× 过取（108MB/层 vs top-8 实际消费
> ~30MB），Windows 实测为负收益」），取消后由计算按需缺页，madvise 页数不变、区间减半。
> 代价：top-8 的 down 列带缺页延迟进入关键路径（页数 ≈ 8×512 ≈ 4.1K 页/层 ≈ 2.0×10⁵ 页/token），
> §4 未把它计入 Δ。

### 3.5 伪代码

```c
/* ---- Hook 1：层入口（decode 专用入口；prefill 仍走原 vqf_stream_layer_advance）---- */
void vqf_stream_layer_advance_decode(STModelWeights *w, int layer) {
    /* 非专家段：保持现状（整层 DONTNEED(l-keep) + 整层 WILLNEED(l+1)） */
    for (seg = 非专家段) { DONTNEED(layer-keep); }
    for (seg = 非专家段) { WILLNEED(layer+1); }          /* 跨层重叠保留 */
    /* down：D1 只看不预读；D2 完全不动作 */
    if (g_sa.down_mode == SA_DOWN_WHOLE) DONTNEED(down, layer-keep);
    /* 专家段（gate/up）：不在此处理 —— 由 Hook 2 按 A_l 收敛 */
}

/* ---- Hook 2：选路后（在 st_moe_ffn_sparse_q4 的 vqf_ffn_prefetch 点）---- */
void vqf_ffn_prefetch(const STModelWeights *w, int layer, const int *sel, int tk) {
    ...既有 EW_PREFETCH 逻辑（保持不变）...
    if (!g_sa.active) return;
    uint8_t *R = g_sa.res + (size_t)layer * RB;
    /* 1) 驱逐 R \ A（对数 ≤ 8，实际 ≤ tk 个位） */
    for (e = 0; e < ne; e++)
        if (bit(R,e) && !in_sel(e)) {
            DONTNEED(gate 段 e);      /* 专家段整页对齐，各 1 次调用 */
            DONTNEED(up   段 e);
            clr(R,e);
        }
    /* 2) 预取 A（≤ 2×tk 次调用），并记账 */
    for (j = 0; j < tk; j++) {
        int e = sel[j]; if (e < 0 || e >= ne) continue;
        if (!bit(R,e)) { WILLNEED(gate 段 e); WILLNEED(up 段 e); }
        set(R,e);
    }
}
```

**Hook 2 的现有挂点（实测，非假设）**

| 路径 | 是否已挂 `vqf_ffn_prefetch` | 位置 |
|---|---|---|
| `st_moe_ffn_sparse_q4`（单 token 稀疏，**两架构共用**） | **已挂** | [L13027](../src/model/vllm_safetensors.c#L13027) |
| `st_moe_ffn_sparse_q4_batch_arm`（**aarch64+dotprod 的批式/prefill**） | **已挂** | [L14959](../src/model/vllm_safetensors.c#L14959) |
| `st_moe_ffn_sparse_q4_batch`（x86 批式） | 无 | [L14394](../src/model/vllm_safetensors.c#L14394) |
| `st_moe_ffn_sparse_q8`（q8 稀疏） | 无 | [L12442](../src/model/vllm_safetensors.c#L12442) |

⇒ **形态 A 的专家级动作必须加「decode 守卫」**（或改走独立 decode 入口）。原因：aarch64 批式
路径**已经**在逐 token 调该 hook，而 prefill 的激活集 ≈ 全体专家，若不加守卫会把 R_l 写满
并触发错误的专家级驱逐。q8 路径若将来也要支持，需另行挂点（本设计只针对 q4）。

调用位置在 router 之后、`vllm_tp_parfor` 之前（[L13027](../src/model/vllm_safetensors.c#L13027)
早于 [L13140](../src/model/vllm_safetensors.c#L13140)）⇒ **单线程段，无并发问题**。

## 4. 预期收益与代价（30B-A3B，N1 t32，Δ_L0 = 277.5 ms）

按 33.8 ns/页换算（与 §1.2 同法）：

| 项 | 页数/token | 预期 Δ | 备注 |
|---|---|---|---|
| 非专家段（保持现状，D+W） | 248K | +8.4 ms | 3.0% 字节 |
| gate/up 驱逐 `R\A`（≈7.5 专家 × 2 张量 × 216 页/层） | 156K | +5.3 ms | **区间与 ne 解耦的证据** |
| gate/up 预取 `A`（16 段 × 216 页/层） | 166K | +5.6 ms | ≈0%（受张量 offset 仅 64B 对齐影响 ≤ +1 页/段、≤0.46%） |
| down（**D1** 整层 DONTNEED） | 1.33M | +44.8 ms | 唯一大项 |
| **合计（D1，默认）** | **1.90M** | **≈ 64 ms** | **Δ_A/Δ_L0 ≈ 0.23** ✅ |
| 合计（D2，down 全不动作） | 0.57M | ≈ 19 ms | Δ_A/Δ_L0 ≈ 0.07 ✅（RSS +5.06 GiB） |

> 上表**未计入**两项：① D1 取消 down 的 WILLNEED 后，top-8 down 列带转由计算按需缺页
> （≈2.0×10⁵ 页/token）的延迟；② 激活专家的首次 fault/建 PTE 成本（现状亦有，量级相近）。
> 故 64ms 是**估计**而非承诺。

**RSS 账（稳态）**

| 档 | 组成 | 估计 |
|---|---|---|
| 现状 stream keep=1（N1 实测） | 常驻段 + 1~2 层整层 | 486~556 MB |
| 形态 A / D1 | 现状 + 每层 8 专家的 gate/up 段常驻（48 × 13.5 MiB = 648 MiB） | ≈ 1.2 GiB |
| 形态 A / D2 | D1 + down 全量常驻（48 × 108 MiB = 5.06 GiB） | ≈ 6.2 GiB |

⇒ **D1 是默认档**（+0.7 GiB 换 ≈ −214 ms）；D2 仅在用户显式开启时使用。
两者在 15.6GiB 板端均可跑（现网 30B 8K 场景峰值 2.92GB / RSS 1.09GB，外加 KV 2.35GB）。

> **乐观性声明**：上表假设「33.8 ns/页」对缩小后的区间仍成立，且未计入
> 新增按需缺页的延迟。它是**设计目标**，不是收益承诺；实测门槛见 §7。

## 5. 与既有开关的关系

| 开关 | 关系 |
|---|---|
| `VLLM_EW*`（专家窗口） | **互斥**：EW 激活即接管层入口钩子（[L686-L691](../src/model/vqf.c#L686-L691)）。形态 A 不参与；EW 原型语义不动 |
| `VLLM_DN_D2` | **不建议叠加**：D2 是匿名内存 repack（+5.06 GiB、不可 `DONTNEED` 回收），与形态 A 的「文件页可驱逐」前提冲突；叠加会双重占内存 |
| `VLLM_VQF_STREAM_COLD` | 正交但叠加即「专家段驱逐 + 丢页缓存 = 真回盘」，板端须单独实测 |
| `VLLM_VQF_STREAM=N`（keep） | keep 仍管**非专家段**的落后层数与 down(D1)；专家段由 R_l 独立记账，不受 keep 影响 |
| `vqf_stream_evict_above()`（res policy） | 显式释放时必须**同时清空 R_l**（否则记账高估驻留） |
| `--sparse-attn` / L3 / 前缀复用 / ACTQ | 正交，不涉及 |

## 6. 正确性论证

### 6.1 A≡C
本方案只调用 `madvise(DONTNEED/WILLNEED)` 与既有的 `posix_fadvise`，不修改任何权重字节、
不重排浮点归约、不改变内核读取路径的数值语义。页由文件按字节重建
（`MAP_PRIVATE` 只读干净页）⇒ **位级一致**，判据 = TOKIDS 逐位相同。

**已获本地闭环证据（同族改动）**：上游探针的 L0–L4 五档（同一族「只改 madvise 区间」）已在
**真实 MoE** 上验证 —— 本地把 `Modl/Qwen3-30B-A3B` 转 q4 VQF（17,665,601,544 B，与 N1 归档
同尺寸）后，六档 TOKIDS 全为 `151667` 逐位相同，且 `[STREAM-PROBE] expert_segs=3` 证明专家段
分支生效（详见 [PRE_REG_STREAM_EXPERT_GRAIN_PROBE.txt](PRE_REG_STREAM_EXPERT_GRAIN_PROBE.txt) §6）。
注意：**x86 缺省轨是 s16 近似轨**，该结论在显式 `VLLM_ACTQ16=0 VLLM_ACTQ=0` 下取得。

### 6.2 记账失准的方向必须保守

| 失准 | 后果 | 是否安全 |
|---|---|---|
| R 低估实际驻留（漏记） | 少驱逐 ⇒ RSS 略高 | 安全（只影响内存，不影响数值） |
| R 高估（把已驱逐的记为驻留） | 多发一次幂等 DONTNEED | 安全（幂等） |

⇒ R 只需是「驻留下界的记账」，**不需要精确**。

### 6.3 prefill 与 decode 的切换（关键）

prefill 阶段单个 mini-batch 内激活集 ≈ 全体专家 ⇒ R 会在 prefill 中被写满，若沿用会退化为「整层」。
**注意：aarch64 批式路径已经挂了 Hook 2**（[L14959](../src/model/vllm_safetensors.c#L14959)），所以：

- **形态 A 的专家级动作只在 decode 生效**：Hook 2 内加 decode 守卫（或改走独立 decode 入口）；
  默认关时整条路径不触发 ⇒ prefill 逐字节现状；
- decode 首次进入前调用一次 `vqf_sa_reset()`：对全部专家段发**整层 DONTNEED 一次**
  （区间 = 现状单次量级，一次性成本），并把 R 全清零；
- 之后 R 从空集单调重建（首 token 区间 0，第 2 token 起进入 §4 稳态）。

`vqf_stream_evict_above(keep)` 与模型重载（`w->vqf_map` 变化）同样走 `vqf_sa_reset()`。

### 6.4 幂等与边界
- `is_expert` 判定沿用已落地的 MoE 几何门（`arch.n_experts·moe_ffn == ffn_dim`，
  [vqf.c L708-L738](../src/model/vqf.c#L708-L738)）⇒ 稠密文件的同名张量不受影响。
- 专家段整页对齐：`expB = 884736B = 216 页`，但 **张量 `offset` 只保 64B 对齐**
  （[conv_main.c L303-L307](../vqf_convert/src/conv_main.c)），须在实现期把
  **offset 页对齐纳入几何自检**（偏差 ≤0.46%，且多余页与相邻专家共享）。
- `q2mix` 尾段（`st_ffn_q4_layer_off` 的层号重映射，[L2352-L2358](../src/model/vllm_safetensors.c#L2352-L2358)）
  与逐层 seg 的「`offset + l·step`」线性假设需要单独核对；本设计与探针均假定**纯 q4 单文件**
  —— 同样的假设也存在于既有的 `vqf_ew_setup` 与 `vqf_ffn_prefetch_resolve`
  （[vqf.c L909](../src/model/vqf.c#L909)、[vqf.c L1149](../src/model/vqf.c#L1149)）。

## 9. 风险与红线

| 风险 | 说明 | 处理 |
|---|---|---|
| 收益不达预期 | 若命中率/页表成本假设不成立（33.8ns/页不适用于缩小区间、新增缺页延迟过高） | P-A-1 不达标即按预注册关闭方向，如实记录 |
| 板端 I/O 重叠损失 | 专家段预取移到选路后，失去跨层重叠 | P-A-3 板端实测；必要时启用 §8.2 预测式预读 |
| RSS 超预算 | D2 的 down 常驻与 KV 争内存 | D1 默认；D2 需显式开启并做 P-A-2 |
| 记账与真实驻留偏差 | 见 §6.2 | 保守方向设计；不加精确性假设 |
| **prefill 污染 R_l** | aarch64 批式路径**已挂** Hook 2（[L14959](../src/model/vllm_safetensors.c#L14959)），prefill 激活集≈全体专家会把 R_l 写满并触发错误驱逐 | decode 守卫 + `vqf_sa_reset()`；默认关时整条路径不触发 |
| 误触加密档 | 加密 VQF 页为脏 COW，`DONTNEED` 会丢解密数据 | 形态 A 仅对明文 VQF 生效；沿用 setup 的 REFUSED 分支，实现期再加一道 `flags & VQF_FLAG_ENC` 门 |
| `q2mix`/多文件组合 | 层号重映射破坏 `l·step` 假设 | 本设计限定纯 q4 单文件；其它组合保持现状路径 |

**红线复述**：只改 PTE/页缓存；不碰浮点序；不动加密档；不进近似轨（不加 `--sparse-attn`、
不进 FAST）；默认关 = 逐字节现状；探针/形态 A 转正须用户显式批准，不得 push/PR。

**结论（诚实口径）**：
- **判据裁决：P-A-1b PASS（0.203）、P-A-2b PASS（按冻结形式）、P-A-1t FAIL（0.914 > 0.90）**。
  依 §5 第 3 条（P-A-3(b) 失败 ⇒ 关闭形态 A）：**形态 A 不转正，`VLLM_SA` 保持默认关**，
  实现作为可选档保留，不改既有语义。
- **设计目标只在「建页量」这一轴达成**：madvise 覆盖页数 **−79.7%（D1）/ −95.9%（D2）**，
  但实际 minor fault 仅 **−8.4%（D1）** ⇒ L0 那 4.02M 页/token 的区间里**绝大多数是本 token
  并不访问的页（区间过取）**，在介质受限端驱逐它们几乎不产生时间代价。
- **板端时间收益 A1 −8.6%（未达 ≥10% 门槛）**。板端是**介质受限**端（冷 prefill 277 s /
  17.67 GB ≈ 64 MB/s）⇒ 与「该端测不到页表成本轴」的既有判定一致。
- **内存维度未达成「只驻留激活专家」（本轮新发现）**：`R_l` 记账只驱逐 `R_l \ A_l`，
  故每层仍常驻「上一 token 的 8 个专家」——A1 的 `rss_end` 在 decode 期涨到 **1.38 GiB
  （L0 的 2.36×，增量 ≈0.80 GiB，恰卡在 §7B 的 0.8 GiB 门槛上）**；A2 的 down 完全不驱逐
  ⇒ 48 层 down 全量累积，`rss_end` **6.33 GiB（L0 的 10.8×）**。
  §7B 的 `rss_after_prefill` 探针**看不到**这段增长（缺口已留档，下一轮须把 `rss_end` 写进判据）。
- **A2 的 decode 0.687（−31.3%）不可据此转正**：§7B 已冻结 A2 为辅助/不作判据，且其
  6.33 GiB 驻留在 15.6 GB 机型上无部署余量。要转正须另立预注册。
- **收益判据仍只待 N1（P-EW-1 / P-A-1）**：若「成本 ∝ 区间」在页表主导端成立，被砍掉的
  79.7% 区间才可能兑现为时间。**在拿到该数据前不得转正**（红线 §5）。

**勘误（本轮先修后测；引用旧数据须注意）**：本轮先定位并修复了一个实现层 bug——`vqf_sa_sync`
原挂在 `vqf_ffn_prefetch` 末尾（后者在 `VLLM_EW_PREFETCH` 未开时提前 return）**导致专家级同步
从未执行**；且层入口「跳过 gate/up 整层驱逐」原为无条件、prefill 期无人驱逐 ⇒ 驻留曾涨到 7.75 GB。
修复 = `warm` 标志 + 同步改名 `vqf_sa_sync_token` 并独立挂在 top-k 选路点。
⇒ 旧 binary `2ecd48af…`/`eed8f2d7…` 的 A1 数据（pages_sum 1,543,668、decode −4.8%、rss 7.75 GB）
**只反映「调用形态」，不代表形态 A，已作废**（详见 `PRE_REG_STREAM_SA.txt` §7B 跑前勘误）。

**第 4 层 · 两个目标的拆分 + 层尾驱逐 `VLLM_SA_EVL`（预注册 §8，判据冻结后实测）**

实测迫使我们把「只驻留激活专家」拆成**两个必须分开命名**的目标（混用会导致判据写错）：

| 目标 | 定义 | 状态 | 证据 |
|---|---|---|---|
| **A「稀疏」** | 驻留集不含**任何非激活专家** | **已达成** | gate/up 过取 = 0%：pages_w = 166,170 页/token，解析值 8×2×216×48 = **165,888 ⇒ 1:1** |
| **B「紧致」** | 驻留量 ≈ **单层瞬时**（≈13.5 MiB/层） | 机制达成、**判据未达标** | 见下 |

并纠正一条**因果链**：**压 `pages_sum` 压不到时间**。L0 是 8.04M 页 vs 95k 缺页（84.5×），
A1 是 1.63M vs 87k（18.7×）——差距收窄 4.5 倍，板端时间只从 −0% 走到 −8.6%
⇒ **过取的页本来就不产生缺页**。（另：`R_l` 在选路后即 `:= A_l`，**没有驱逐残留**；
1.38 GiB 是 48 层激活集的**并**，不是残留。）

**新增机制** `VLLM_SA_EVL=1`（默认关，需配 `VLLM_SA=1`）：进入 layer l 时把「上一层已用完的
激活集」`R_{l-keep}` 的 gate/up 段 DONTNEED 并清空记账（`vqf_sa_evict_layer`）。
实测（板端 ctx=256 n=32，binary `d1ea20ad…`）：

| 臂 | rss_end | decode ms/tok | pages_sum/tok | minflt/tok |
|---|---|---|---|---|
| L0 | 610,408 / 611,368 kB | 1154 / 1122 | 8,040,948 | 95,126 |
| A1 | 1,445,596 / 1,446,968 kB | 1036 / 1029 | 1,631,796 | 87,141 |
| **A1E** | **803,012 / 806,256 kB** | **1094 / 1068** | 1,869,396 | 95,116 |

- G0 PASS（六臂 TOKIDS 全 151667）；**P-E-1 FAIL**（804,634 > 715,746 kB = L0 + 0.1 GiB）；
  **P-E-2 PASS（勉强）**：1081/1032.5 = **1.047**（n=64 复测 1.040）。

**归因（判据外诊断；`[SA-STAT]` 新增 `rss_anon/rss_file` 拆分）**：

| 臂 (n=64) | `rss_file` t=64 | file − L0file | `rss_anon` t=64 | decode |
|---|---|---|---|---|
| L0 | 501,608 kB | 0（基准，全程平） | 121,548 | 962 |
| A1E | 714,056 kB | **+207.5 MiB** | 121,560 | 937 |
| A1 | 1,354,448 kB | **+832.9 MiB** | 121,556 | 901 |

- **`rss_anon` 三臂逐点完全相同**（+0.24 MB/token ≈ KV 预测 0.19）⇒ **分配器/KV 泄漏被排除**；
  差异全在 **`rss_file`（mmap 权重页）**。
- **EVL 生效量可精确核对**：file(A1) − file(A1E) = **625.4 MiB**，预测应移除 648 MiB ⇒ **96.5%**。
- **残留 = 门槛（107.4 MiB）的 2.03×**，**与 EVL 机制无关**；其来源**只定位到类别**
  （mmap 权重页，非 anon），具体候选（**未验证**）：(a) 边界层 `layer = nl−1` 永不被驱逐；
  (b) SA 的小区间 WILLNEED 引起 readahead 外溢、永不被 expert-granular DONTNEED 回收。
  判别实验（下轮、须另立预注册）：驱逐区间页对齐后向外扩 N 页。
