文件命名
------------------------------------------------------------------------------
{arm}_{tag}_r{round}.log           该 arm 该轮引擎日志，关键行为证据在此
{arm}_{tag}_r{round}_t{turn}.json  单次请求的原始响应（含 metrics / timings）
arm：llama        = llama.cpp llama-server（-t 4 -ngl 0，默认前缀缓存）
     vllm_s1      = 本版逐层（VLLM_VQF_STREAM=1）
     vllm_s0      = 本版全层
tag：165 / 330 / 600 = 提示词长文重复段数，实测 prompt 约 1997 / 3977 / 7217 token
     （README §7 记作 2.0K / 4.0K / 7.2K）
turn：1 = 首次整段 prefill（本版为整段；turn2/3 为前后缀追加追问，两侧均命中前缀复用）
      ⚠ turn* total_s 含 decode 时间（本版 40~64 token，llama.cpp 常 6~17 token），
        故「复用轮时延」一律取响应里的 metrics.prefill_ms（kv2_sum2.py 已如此处理）

harness/ 内容
------------------------------------------------------------------------------
kv2_run2.sh           主测试脚本（参数化 SEGS/ROUNDS/TAG/ENGINES/STREAMS；含 arm 启停、
                      drop_caches、预热丢弃）。**已修复 md5 缓存目录缺失的缺陷**
kv2_sum2.py           汇总器：解析各轮 json + summary.txt，输出 REPORT.txt（增量 token 口径）
kv2_chain.sh          自主收尾链：等 full 结束→汇总→抬 max_seq→跑 16K→回滚→汇总 16K
                      （本轮的 16K 段因用户指示在 8K 第 2 轮后停机而未执行）
kv2_stop_after_r2.sh  停机看门狗：掐断 kv2_chain.sh，等 8K r2 最后一个 arm 收尾后杀掉
                      kv2_run2.sh 与两侧引擎，追加 NOTE_STOP，并生成 REPORT.txt
patch_vqf_max_seq.py  VQF 头 max_seq 读写（--dump/--set N/--restore），与仓库
                      tools/bench/patch_vqf_max_seq.py 同一份

复现步骤
------------------------------------------------------------------------------
0. 注意：kv2_run2.sh 的位置参数顺序为  <SEGS> <ROUNDS> <TAG> [ENGINES] [STREAMS]，
   SEGS 是**逗号分隔**列表。（20260915 目录的 MANIFEST 曾把顺序写错，特此更正。）
1. 上传 harness/ 到板端同目录，跑前确认两侧权重 md5 与本文件一致
2. 2K/4K/8K：sh harness/kv2_run2.sh "165,330,600" 3 full_v2 "vllm,llama" "1,0"
   （结果落 /mnt/emmc/kv2_full_v2/，L3 目录 /mnt/emmc/kv2_l3_full_v2/）
   若要复现「8K 只跑 2 轮」，另起 harness/kv2_stop_after_r2.sh 作看门狗
3. 16K：先 python3 tools/bench/patch_vqf_max_seq.py --set 20480 <model.vqf>
        再 sh harness/kv2_run2.sh 1300 1 16k_v2 "vllm,llama" "1,0"
        测完用 --restore 回滚
4. 汇总：python3 harness/kv2_sum2.py <结果目录>
