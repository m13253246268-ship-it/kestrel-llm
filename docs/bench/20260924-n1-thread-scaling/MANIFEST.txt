二、运行前冻结的口径（预注册，未事后改动）
================================================================================
问题：8B（Qwen3-VL-8B，VQF q4，全层驻留）在本机，计算并行度随线程数 T 是否带来加成？
臂  ：T ∈ {1,2,4,8,16,32,64}
固定：OMP_NUM_THREADS = VLLM_THREADS = T（引擎计算线程池唯一入口 vllm_tp_init）；
      VLLM_TP_SPIN 未设（代码默认 200000）；VLLM_TP_BIND 未设（默认不绑核）；
      --wmode q4、全层驻留（不设 VLLM_VQF_STREAM）、不开近似轨（不设 VLLM_ACTQ）。
命令：vllm_kestrel --stream-test --model <dir> --warmup --stream-ctx 512 --stream-n 32
页缓存：**热**（16.3 GiB 权重 << 245 GiB RAM；每格前有全局丢弃预跑，格内自带 --warmup 丢弃 1 prefill + 8 decode）
轮次：3 轮交错（r1 升序 / r2 降序 / r3 升序），**每格一个独立进程**；单实例 flock 锁，防并发污染
G0 有效性门：同轮内所有 T 的 TOKIDS 必须逐位相同且 token 数相同 —— **21/21 格全 PASS**
主要量：prefill 秒（`[STREAM] prefill N tokens in X.XXXs`）、decode ms/tok
线程档核验：每格采样引擎进程 /proc/<pid>/status Threads，实测 nlwp_max == T（1/2/4/8/16/32/64）
             —— 证明 OMP_NUM_THREADS 确实生效，不是"设了没起作用"

补测（post-hoc，主扫描完成后另跑，同口径）：T ∈ {32,40,48,56,64} × 4 轮（bench/probe/）
default 检查（post-hoc）：env -u OMP_NUM_THREADS -u VLLM_THREADS，跑 2 次（bench/default/）

已作废的一轮：/root/bench_run_VOID_2instances.log（首次启动时旧实例未退出，两实例并发、
互相污染计时；仅 t64 受影响，其余档位与干净轮复现一致，故整轮判 VOID 并归档留证）。

================================================================================
四、必须一并引用的边界
================================================================================
1. 这是 **Neoverse-N1 / aarch64 云实例**的数据，**不是 RK3588 板端数据**；绝对数字不跨机器、
   不跨 session 外推。README「性能」章的 RK3588 数字不可与本表并列或混引。
2. RK3588 的「--threads 8 比 4 慢 1.8~2.5 倍」是 **big.LITTLE 特异性**结论（t8 会把 4 个 A55
   小核拉进 GEMM 并行区），**不可作为本机预期**；本机是同构 64 核，曲线完全不同。
3. 本机无 cpufreq / thermal 节点（虚拟化），**无法记录 governor 与温度**，也不能排除宿主侧
   频率变化；steal_ticks 全程为 0 是唯一可得的"未被抢占"证据。
4. 口径为**热页缓存**；冷页缓存（首次从盘读 6.15 GiB）不在本表。
5. 本表**只测计算并行度**，不开任何近似轨（VLLM_ACTQ 未设），G0 已证 7 个线程档 TOKIDS 逐位相同
   —— 即"多线程不改数值"在本机成立（与 README「并行按 idx 静态切分、不改浮点步序」一致）。
6. 只测单请求串行（--stream-test 骨架），**不含并发服务场景**；服务工作线程 `--threads` 与
   计算线程池无关，本表未涉及。
7. 最大 RSS 只在 4.21~4.32 GB 间（全层驻留），线程数不改内存口径。
8. 补齐说明（诚实登记）：`--stream-test` 日志在 T=1 档会被 grep 判为 binary（含非 UTF-8 字节），
   解析时须用 `grep -a`；首轮曾因误判导致该格汇总行缺数，Python 解析器不受影响。
