PRE_REG_STREAM_EXPERT_GRAIN_PROBE.txt -- 方向 E（逐层驻留的权重读取降到「专家级」）立项探针
跑前冻结（探针先行）。ASCII 判据编号。禁止事后改阈值。

================================================================================
0. 要决定什么
================================================================================
是否立项「方向 E」：把逐层驻留（VLLM_VQF_STREAM）档下 decode 的权重读取/页驻留粒度
从「整层」降到「专家级」，使每 token 的 madvise 区间与「本 token 实际激活的
top_k=8 专家」成正比，而不是与整层（128 专家）成正比。

已确认的两轴事实（见 §1）：
  · 计算是稀疏的：decode 只算 top_k=8 个激活专家（st_moe_ffn_sparse_q4）。
  · 但驻留是整层的：vqf_stream_setup 按 step=bytes/nl 建 seg，对 q4_gate/up/down
    而言该段含全部 128 专家（per-layer=334.1MB）；层入口对整个 l+1 层发
    WILLNEED、对 l-keep 整层发 DONTNEED。

本探针不实现「专家级驻留」，只量该方向的**乐观地板**：把专家段的 madvise 区间
直接清零（纯按需缺页）后 decode 剩多少。地板达标才授权设计真正的
「常驻集有界 + 专家级驱逐」策略（形态 A）；地板不达标则整条方向关闭。

================================================================================
1. 背景数字（本轮实测，引用须同引口径）
================================================================================
N1/aarch64（Neoverse-N1 64 核 / 245GiB / 页缓存热），Qwen3-30B-A3B q4 VQF 17.67GB：
  full    decode 109.5 ms/tok（t32）
  stream  decode 387.0 ms/tok（t32）  ⇒ Δ = +277.5 ms/tok
  Δ 在 T=32/40/48/56/64 上为 277.5/281.0/293.0/292.0/306.5（几乎不随算力变）
  逐层 TOKIDS 与全层逐位相同（md5 b1304c6459e0，0/32 差异）
  来源 docs/bench/20260925-n1-moe-30b-a3b/{MANIFEST.txt §3.2, bench/t32probe/}

机制量化（本探针的依据）：
  现档每 token madvise 区间 = 334.1MiB/layer × 48 × 2(WILLNEED+DONTNEED)
                            = 32.0 GiB ≈ 8.21M 页
  277.5 ms / 8.21M 页 ≈ 33.8 ns/页（syscall 计数被排除：1056 次/token 仅 ≈263µs/次）
  跨模型反证：8B（稠密 6.60GB）Δ=+157ms；30B-A3B（MoE，激活 ~1.6GB）Δ=+398ms。
            Δ 之比 2.54 ≈ 模型字节比 2.68，≠ 激活字节比 0.24
            ⇒ 开销 ∝ 被 madvise 的整层区间字节，不 ∝ 激活权重
  来源 wiki/性能与基准.md L44-49（板端 v1.0 --stream-test 冷页缓存，8B/30B）

几何（专家级收窄的可行性边界）：
  gate/up 专家段 = 768×2048 elt → 884736 B = 216 页（精确整页对齐）⇒ 可 0% 过取
  down         = rows=d, cols=ff, 4 行组 221184 B=54 页；专家列带 1728 B/行组
                 → 页 4096 B 与专家带 1728 B 不对齐、页被邻专家共享
                 → 单专家 3.33×，top-8 并集地板 ≈ 2.3×（**down 不可达 0%**，已决策接受）
  收窄后每层理想区间 ≈ attn/norm 10.1 + gate/up 13.5 + down 16 ≈ 40 MiB（vs 334 MiB）

================================================================================
2. 装置
================================================================================
主装置（**出判据**）：N1/aarch64 云实例（245GiB；L3 档需放弃专家段驱逐，RSS 会增长到
  接近全模型，故只有 245GiB 机器能跑 L3）。模型 Qwen3-30B-A3B-q4 VQF。
  同 boot、每格一个独立进程、flock 单实例、升/降序交替、2 轮取中位。
  线程：OMP_NUM_THREADS = VLLM_THREADS = 32（decode 最优平台）；测后清空。
  页缓存：**热**（每格 --warmup + 脚本开头全局丢弃预跑）——本探针的对象是
  PTE/madvise 成本，冷缓存会把 eMMC I/O 混进来。

复现装置（**只作旁证，不出判据**）：RK3588 15.6GiB 板端仅可跑 L0/L1/L2/L4；
  L3 在 30B 上不可跑（RSS 超 RAM）。板端结论只能由形态 A 实装后另立项验证。

x86（本机 MinGW）：**只作功能/位级自检**（探针默认关零回归 + 各档 TOKIDS 逐位一致），
  不得出任何性能结论。

新开关（默认关；未设 = 逐字节现状）：
  VLLM_STREAM_PROBE=1  L1：只保留整层 DONTNEED(l-keep)，关闭整层 WILLNEED(l+1)
  VLLM_STREAM_PROBE=2  L2：只保留整层 WILLNEED(l+1)，关闭整层 DONTNEED(l-keep)
  VLLM_STREAM_PROBE=3  L3：**专家段（q4/q8_gate/up/down 且 MoE 几何成立）不做任何
                          madvise**（纯按需缺页）；非专家段（attn/norm 等）行为同 L0。
                          = 「区间→0」乐观地板；RSS 无界（故意）
  VLLM_STREAM_PROBE=4  L4：区间与 L0 完全相同，但每次调用按 16 片等分发出
                          （syscall 计数对照，模拟专家粒度调用数）
自证：每个探针档起动时打一行
  `[STREAM-PROBE] mode=<n> ...`（未设时无此行）；
  mode=3 且文件中无 MoE 专家段时额外打 WARN 并声明退化为 L0。

测量：`--stream-test --model <30b-q4-dir> --warmup --stream-ctx 256 --stream-n 32`
指标：`[STREAM] decoded 32 tokens, X ms/tok`（32-token 均值）。
      **禁止引单 token [DEC-SINGLE]**（M8）。对照档 F = 不设 VLLM_VQF_STREAM。

================================================================================
3. 臂与判据（冻结）
================================================================================
  F     不设 VLLM_VQF_STREAM                -> decode_full
  L0    VLLM_VQF_STREAM=1                   -> 现状（整层 WILLNEED + 整层 DONTNEED）
  L1    VLLM_VQF_STREAM=1 VLLM_STREAM_PROBE=1
  L2    VLLM_VQF_STREAM=1 VLLM_STREAM_PROBE=2
  L3    VLLM_VQF_STREAM=1 VLLM_STREAM_PROBE=3   （**核心探针**）
  L4    VLLM_VQF_STREAM=1 VLLM_STREAM_PROBE=4

  Δ_X := decode_ms(X) - decode_ms(F)      （X ∈ L0..L4）

  G0（validity，否则整轮 VOID）
    - 各档自证行与 mode 值一致；n=32；decode 段 > 0；两轮同档抖动 <= 3%。
    - **TOKIDS 门：F 与 L0..L4 全部逐位相同**（只动 PTE/页缓存，浮点序零改动）。
      任一档 TOKIDS 不同 = VOID（先查是否误触数值路径）。
    - 零回归自证：不设 VLLM_STREAM_PROBE 时，L0 的 TOKIDS 与本改动前的基线二进制
      逐位相同（x86 自检承担；见 §6）。
    - L4 若在 x86 上自检时 mode 不生效（Windows 无 madvise 语义差异）不影响判据，
      但须在 N1 复验自证行。

  P-EW-1（机制，决策前提）
      Δ_L3 / Δ_L0 <= 0.35
        达标 => 机制成立：专家段区间占逐层开销 >= 65%，授权立项形态 A（设计
                「常驻集有界 + 专家级驱逐」策略，down 按页带、接受 2.3× 地板）。
        不达标 => **方向关闭**：逐层开销不由专家段区间主导，不再投入实现。
      （Δ_L3 是乐观地板：真实形态 A 还要付「激活段重新 fault/读回」与驱逐 syscall，
        故达标只授权立项，不是收益承诺。）

  P-EW-2（syscall 计数控制）
      Δ_L4 <= 1.05 × Δ_L0
        达标 => 调用次数（16×）非主导项，专家级多次小调用是安全的。
        不达标 => 形态 A 的专家级驱逐必须**合并区间**（批量驱逐），不得逐专家调用。

  两判据均在 2 轮中位值上评估；同 boot 复测抖动应 <= 1%（历史口径）。
  L1/L2 不设阈值，只作归因（分离 WILLNEED 与 DONTNEED 的贡献）。

================================================================================
4. 已知局限（引用结果时必须同引）
================================================================================
(a) Δ_L3 是**乐观地板**：它假设专家段一页都不必碰。真实形态 A 仍需把本 token 激活的
    专家页 fault 回来（约 1.6GB/token 的按需缺页），且 down 受页共享限制地板 2.3×。
    故 P-EW-1 达标只授权「立项设计」，不承诺最终收益。
(b) L3 放弃专家段驱逐 ⇒ RSS 无界（30B 上会涨到接近全模型）。它是**判别实验**，
    不是可用档；绝不可把 L3 当生产配置发布或在 15.6GiB 板上跑。
(c) 本探针只覆盖 **decode 单请求串行**（--stream-test 骨架），不含并发服务；
    prefill 侧逐层 Δ 极小（N1 t32 全层 6.892s vs 逐层 6.981s），本方向不为 prefill。
(d) 本探针**不采集** sel[] 复用率。复用率采集已在形态 A 预注册
    （docs/PRE_REG_STREAM_SA.txt，开关 VLLM_SA_SELPROBE=1）定义为**只读诊断项**：
    它用于解释稳态 |A_{t-1}\A_t| 的实际大小，形态 A/D1 的驱逐策略本身不依赖它
    （保留集取本 token 真实激活集）。本归档无 sel 落盘，不得臆测 6% 的 i.i.d. 估计。
(e) 静态热窗路线（VLLM_EW，专家窗口）**不在本探针的授权范围**：其层入口驱逐的参照系是
    「本层全体非热专家段」，H=8 时 310.5MiB/层（仅 DONTNEED），相对「激活 8 专家段」
    仍是 23 倍量级。注意：**归档从未实测 EW**（wiki 只记「VLLM_EW* 源文件未给收益数字」，
    ≠ 实测零收益；且其区间约为现状 W+D 的一半量级，按「成本 ∝ 区间」假设本应有可观收益）。
    故 EW 的成败是**待证假设**，由本探针 L1/L2/L3（W/D 拆分 + 区间→0 地板）间接裁决；
    本探针若达标，走的也是「动态激活集」路线，不是静态热窗。
(f) 逐层驱逐**不减少**每 token 的权重读取总量，只改变数据来源与 madvise 区间
    （include/model/vqf.h L64-65）。形态 A 同样不减少读取总量，只减少区间。
    对外表述不得写成「减少了读取量」。
(g) 待办的实现期检查（本探针不涉及）：EW/PF 的几何自检只验 expB%4096==0，不验张量
    offset 的页对齐（转换器只保 64B）⇒ 专家段可能多跨 1 页（<=0.46%）。形态 A 实装时
    须把 offset 页对齐纳入门控。
(h) down 的 0% 过取在本约束下不可达（页 4096 vs 专家带 1728，页被邻专家共享）。
    要 0% 只能改 VQF 文件布局（专家-major 连续），属格式级改动，须另立项并走质量门。
    （VLLM_DN_D2 是匿名内存 repack，+5.2GB 且不可回收，与省 RAM 目标冲突，不可用。）

================================================================================
5. 红线（本探针必须守住）
================================================================================
1. 只改 PTE/页缓存（MADV_WILLNEED/DONTNEED、posix_fadvise），**不触碰任何浮点求和/
   归约/融合顺序** ⇒ 天然满足位级一致（A≡C），以 TOKIDS 逐位相同为判据。
2. **禁止对加密 VQF 施加任何逐层/逐专家驱逐**（VQF-Enc 页为脏 COW，DONTNEED 会丢
   解密数据）。setup 的 REFUSED 分支不得放宽。
3. 不得与近似轨混同：不加 --sparse-attn、不进 FAST 模式；本方向必须落在精确轨。
4. 默认关 = 逐字节现状；不得改动既有 VLLM_VQF_STREAM / VLLM_EW / VLLM_DN_D2 语义。
5. 未经用户显式批准，不得把探针开关转正为生产默认、不得 push/PR。

================================================================================
7. N1 交接命令（跑前须先确认：模型目录、页缓存热、同 boot）
================================================================================
前提：aarch64 原生构建（binary sha256 记入日志头）；模型 30B-A3B-q4 单目录
      （model.vqf = 17,665,601,544 B）。每格一个独立进程 + flock 单实例；
      升/降序交替；2 轮取中位；脚本开头另有全局丢弃预跑。

共同前缀：
  OMP_NUM_THREADS=32 VLLM_THREADS=32 VLLM_TP_SPIN=200000 VLLM_NPU_FORCE_CPU=1 \
  VLLM_ACTQ=0 \
  ./vllm_kestrel --stream-test --model <30b-q4-dir> --warmup --stream-ctx 256 --stream-n 32
  （VLLM_ACTQ=0 用于显式锁精确轨；ARM 侧 actq16 是编译期恒 0 的桩，无需设置，见 §6
    「x86 默认轨」。每格日志须确认**不含**任何 [ACTQ]/[ACTQ16] 行。）

六格环境变量：
  F : （不设 VLLM_VQF_STREAM，不设 VLLM_STREAM_PROBE）
  L0: VLLM_VQF_STREAM=1
  L1: VLLM_VQF_STREAM=1 VLLM_STREAM_PROBE=1
  L2: VLLM_VQF_STREAM=1 VLLM_STREAM_PROBE=2
  L3: VLLM_VQF_STREAM=1 VLLM_STREAM_PROBE=3   # 仅 245GiB 的 N1 可跑（RSS 无界）
  L4: VLLM_VQF_STREAM=1 VLLM_STREAM_PROBE=4

每格必须落盘自证：
  - 二进制 sha256 / mtime（与构建日志错误行一并核验；不看返回码）
  - model.vqf md5
  - 整机 ENV 头 + load + buff/cache
  - 逐格采样 /proc/<pid>/status 的 Threads（nlwp_max == 32）
  - 引擎 stdout 全文（须含 [VQF-STREAM] enabled 行；探针档须含 [STREAM-PROBE] mode 行）
  - 指标行 `[STREAM] decoded 32 tokens, X ms/tok`
判据：见 §3（G0 / P-EW-1 / P-EW-2）。不达标即关闭方向，禁止事后回改阈值。
