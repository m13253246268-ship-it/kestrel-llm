================================================================================
1. 被测机制（一句话）
================================================================================
把逐层驻留档下**专家段**（q4_gate/up）的驱逐/预取，从「每 token 对整层（含全部 128 专家）
发 WILLNEED + DONTNEED」改为「按每层实际驻留集 R_l 收敛到本 token 激活集 A_l（top-8）」：
  - 层入口只处理非专家段（保持现状）+ down（D1：整层 DONTNEED，不预读）；
  - 选路后（top-k 已定）驱逐 R_l \ A_l、预取 A_l、R_l := A_l。
  - down 只做整层 DONTNEED（1 次/层），不做专家级（页共享 + 列带 1728B < 4KB 页，不可表达）。

诚实边界（引用结果必须同引）：
  · 只改 PTE/页缓存，**不减少每 token 的权重读取总量**，只减少 madvise 区间与页表重建量
    （include/model/vqf.h L64-65）。
  · §4 的 Δ 估计（D1≈64ms）是**设计目标**，不是收益承诺。

2. 装置与开关
================================================================================
主装置（**出判据**）：N1/aarch64 云实例（Neoverse-N1 64 核同构 / 245 GiB / 页缓存热），
  模型 Qwen3-30B-A3B-q4 VQF（model.vqf = 17,665,601,544 B）。
  同 boot、每格独立进程 + flock 单实例、升/降序交替、2 轮取中位。
  线程：OMP_NUM_THREADS = VLLM_THREADS = 32（decode 最优平台）；测后清空。
复现装置（**旁证，不出判据**）：RK3588 15.6 GiB 板端；--threads 4；冷/热页缓存档分别标注。
x86：**只作功能/位级自检**（默认关零回归 + 各档 TOKIDS 逐位一致），不得出性能结论。

新增开关（实现时全部**默认关**；未设 = 逐字节现状）：
  VLLM_SA=1             形态 A 主开关（专家级驱逐/预取 + R_l 记账）
  VLLM_SA_DOWN=whole|keep   down 策略：whole=D1（默认，RSS 有界）/ keep=D2（down 不驱逐）
  VLLM_SA_SELPROBE=1    只读诊断：按层累计相邻 token 激活集复用率 |A_t ∩ A_{t-1}| / tk
                        （零数值影响；用于解释 |A_{t-1}\A_t| 的实际大小）
  形态 A 与 VLLM_EW* 互斥（EW 优先接管层入口钩子）；不建议与 VLLM_DN_D2 叠加（匿名 repack）。

自证行（未设时无输出 => 零回归可核）：
  `[VQF-SA] enabled down=whole|keep nl=.. ne=.. exp=..MB(216页) res=..B stat=..` （一次性；
   非 MoE / 加密 / 未开流式 / 几何或页对齐不符时打 `[VQF-SA] REFUSED: …`）
  `[VQF-SA] enabled` 未出现且 `VLLM_SA=1` ⇒ 该格 VOID（先查 REFUSED 原因）
  `[SA-STAT] tok=.. pages_w=.. pages_d=.. pages_sum=.. minflt_delta=..` （仅 VLLM_SA_STAT=1；
   **独立于 VLLM_SA**，L0 档也会打印 ⇒ 可直接比较建页量）
  注：原规划的 `VLLM_SA_SELPROBE`（sel 复用率）**未实现**——D1 的保留集取本 token 真实
  激活集，不依赖复用率；复用率仅影响稳态 |A_{t-1}\\A_t| 的解释，待需要时再补。

测量：`--stream-test --model <30b-q4-dir> --warmup --stream-ctx 256 --stream-n 32`
指标：`[STREAM] decoded 32 tokens, X ms/tok`（32-token 均值；**禁止引单 token [DEC-SINGLE]**）。

3. 臂与判据（冻结）
================================================================================
  F   不设 VLLM_VQF_STREAM / VLLM_SA                -> decode_full
  A0  VLLM_VQF_STREAM=1                             -> 现状逐层（= 上游 L0）
  A1  VLLM_VQF_STREAM=1 VLLM_SA=1                   -> 形态 A / D1（默认推荐档）
  A2  VLLM_VQF_STREAM=1 VLLM_SA=1 VLLM_SA_DOWN=keep -> 形态 A / D2（高档，RSS 换延迟）

  Δ_X := decode_ms(X) - decode_ms(F)      （X ∈ A0, A1, A2）

  G0（validity，否则整轮 VOID）
    - 四档 TOKIDS **全部逐位相同**（只动 PTE/页缓存，浮点序零改动）。
    - 各档自证行与开关值一致；n=32；decode 段 > 0；同档两轮抖动 <= 3%。
    - 零回归自证：不设 VLLM_SA 时（F/A0）的 TOKIDS 与本改动前基线二进制逐位相同。
    - VLLM_EW 未激活（EW 激活时形态 A 不参与，属 VOID 配置）。

  P-A-1（机制与收益，决策前提）
      Δ_A1 / Δ_A0 <= 0.35
        达标 => 形态 A/D1 有效，授权转正评审（仍需用户显式批准）。
        0.35~0.60 => 弱信号：只授权「保留为可选档 + 继续优化」，不得转正为默认。
        > 0.60   => 关闭形态 A（按 §5 如实记录），不再投入。

  P-A-2（内存，板端）
      D1 档稳态 RSS 峰值 <= 15.6 GiB - KV_peak - 0.5 GiB margin；
      且 D1 的 RSS 峰值 <= A0 的 RSS 峰值 + 0.8 GiB（专家段常驻上限 ≈ 648 MiB 的口径）。
      D2 档单独记录（预期 ≈ A0 + 5.6 GiB），不设门，只作可选档的披露义务。

  P-A-3（板端实际收益与回归）
      (a) prefill：A1 相对 A0 <= +3%；
      (b) decode：A1 相对 A0 有净收益，且改善 >= 10%（Δ_A1 <= 0.90 × Δ_A0）。

  P-A-4（回归与零副作用）
      --test-l3 16 PASS / 0 FAIL；--test-sparse 9/9；
      探针（VLLM_STREAM_PROBE）与形态 A 各自默认关时行为逐字节现状。

  评估口径：全部在 2 轮中位值上评估；同 boot 复测抖动应 <= 1%（历史口径）。
  辅助指标（不作判据）：VLLM_SA_SELPROBE 的 mean_reuse（解释 |A_{t-1}\A_t|）。

4. 口径豁免与漂移归一（M4/M6 显式说明）
================================================================================
  1. **M6 豁免（须用户签署）**：本系列刻意使用**热页缓存 + 同 boot 多配置**——被测对象是
     PTE/madvise 成本，冷缓存会把 eMMC I/O 混入；N1 为云实例无 3D V-Cache 伪影。
     与 M6「冷缓存首槽、一个 boot 跑一个配置」相反，故显式记录豁免理由与适用边界。
  2. **M4 漂移归一**：用同轮内未改动档（F 桶）作漂移锚点；变化 <3% 记噪声。
  3. 每格落盘自证：binary sha256 / mtime（配构建日志错误行，不看返回码）、model.vqf md5、
     整机 ENV 头 + load + buff/cache、逐格 /proc/<pid>/status Threads（nlwp_max == 32）、
     引擎 stdout 全文（含 `[VQF-STREAM] enabled` 与 `[VQF-SA] enabled down=… stat=…` 行）、
     指标行。
     **跑前必核运行体身份**：`sha256sum ./vllm_kestrel` 必须等于新构建产物，且
     `strings ./vllm_kestrel | grep -c VQF-SA` > 0（根目录副本易滞后于 `build-rk3588/`，
     本项目已因此作废过一轮 A/B）。
     **锁精确轨**：x86 上必须显式 `VLLM_ACTQ=0 VLLM_ACTQ16=0`（x86 缺省是 s16 近似轨）；
     ARM 侧 actq16 为编译期恒 0 的桩。

7B. 替代口径（2026-09-25 跑前冻结）：**N1 不可达 ⇒ 以板端出协议级结论**
================================================================================
背景（事实，非协商）：N1（114.215.207.71）22/443/ping 全不通，本机无其凭据 ⇒ §7 的
  P-EW-1/P-A-1 判据无法采集。按用户指示改用板端。**本档是替代口径，不是等价口径**：
  板端为**介质受限**端（模型 17.67GB > RAM 15.6GB，页缓存装不下整模型），
  §7 的「页表成本轴」在本端**测不到**（已由 L1≈L0 两次复现 + L4 零语义对照证伪）。

装置（冻结）：orangepi5plus（RK3588，8 核，RAM 15,964MB）；模型 /mnt/VQF/qwen3-30B-A3B-q4
  （model.vqf 17,665,601,544 B）；binary sha256 `eed8f2d7…`（含 VLLM_SA 与 VLLM_SA_STAT）；
  工作树 /mnt/emmc/saprobe（不动 kestrel_pull）。
口径（冻结）：`OMP_NUM_THREADS=4 VLLM_THREADS=4 VLLM_NPU_FORCE_CPU=1 VLLM_ACTQ=0
  VLLM_SA_STAT=1`，`--stream-test --stream-ctx 256 --stream-n 32`
  （**不用 `--warmup`**：本档每臂前 `sync; echo 3 > /proc/sys/vm/drop_caches` 制造**确定性冷态**，
   `--warmup` 会把缓存热起来、破坏该确定性；N1 档 §7 用 `--warmup` 是因为那里是热缓存口径，
   **两档不可混引**）；A1/A2 交错双轮、L0 双轮（降/升序交替）。**撤掉 F 臂**（17.67GB 全驻留
  必由 swap 主导）。
  （此处在**跑任何臂之前**修正：初稿同时写了 `--warmup` 与 `drop_caches`，二者互斥。）

【跑前勘误 2026-09-25（在跑判据臂**之前**记录；与上一处同级：属装置更正，**不改阈值/口径**）】
  装置行的 binary 由 `eed8f2d7…` 更正为 `203aae7e2b97d34fb98a034990bda51340f2ae44ab0d78c117f4b16d049f9cf8`。
  原因（实现层 bug，已定位、已修复、已在 x86 与板端双向复现）：
  (a) `vqf_sa_sync` 原挂在 `vqf_ffn_prefetch` 末尾，而后者在 `VLLM_EW_PREFETCH` 未开时
      **提前 return** ⇒ 专家级「驱逐 R_l\A + 预取 A_l」**从未执行**（x86 上 A1 的 pages_sum
      曾与 L0 逐位相同 = 8,040,948，是该 bug 的直接指纹）。
  (b) 层入口「跳过 gate/up 整层驱逐」原为**无条件**；prefill 期同步又被批式守卫抑制
      ⇒ prefill 全程无人驱逐 gate/up，驻留涨到接近全量（实测 rss_after_prefill 604MB → 7.75GB）。
  修复：(1) 新增 `warm` 标志——仅「本 token 已完成过专家级同步」才跳过整层驱逐，
        `vqf_sa_set_batch(1)` 与显式释放路径均清 warm（保守回落到现状驱逐）；
        (2) 同步改名公开的 `vqf_sa_sync_token` 并**独立挂在 top-k 选路点**
        （src/model/vllm_safetensors.c，`vqf_ffn_prefetch()` 之后一行）。
  ⇒ 影响（引用本档必须同引）：`eed8f2d7` 的 A1 臂只测到**调用形态**（巨区间 madvise 换成多次小调用），
    **未测到**形态 A 的专家级收敛；其 A1 数据（decode −4.8%、rss 7.75GB）**不代表形态 A**，不得引用。
    `eed8f2d7` 的 L0 臂不受影响（VLLM_SA 关，走现状路径），仍有效。
  判据阈值（P-A-1b/1t/2b）、装置（机/模型/线程）、`drop_caches` 口径**一律未变**。

  【功能门（**非判据**，先跑；仅确认修复在板端生效）】binary `203aae7e…`，ctx=32 n=8，每臂前 drop_caches：
    L0  prefill 228.4s rss_after_prefill=516,884kB decode 1966 ms/tok pages_sum=8,040,948 minflt/tok=95,434
    A1  prefill 228.1s rss_after_prefill=**514,076kB** decode **1631** ms/tok pages_sum=**1,691,412** minflt/tok=89,461
    A2  prefill 228.6s rss_after_prefill=515,608kB decode 1377 ms/tok pages_sum=391,956 minflt/tok=12,764
    三臂 TOKIDS 全 151667（A≡C）；prefill Δ<1%。⇒ 修复在板端生效：sync 真正执行（pages_sum 1,691,412
    ≠ L0 8,040,948）、rss 不再爆（514MB ≈ L0）。本行只作机制自证，**不作判据**。

判据（板端替代口径；阈值同样跑前冻结、禁止事后回改）：
  G0   各臂 TOKIDS **逐位相同**；各臂须打印 `[VQF-SA] enabled …`（A1/A2）；prefill 不得劣化 >3%。

8.0 术语与因果链纠正（**先定死，防止下一轮把判据写错**）
  (a) 两个目标必须分开命名，**禁止混用「只驻留激活专家」**：
      · 目标 A「**稀疏**」：驻留集里不含**任何非激活专家**。
        ⇒ **形态 A 已达成**（gate/up 过取 = 0%：pages_w = 166,170 页/token，
        而解析值 8×2×216×48 = 165,888 ⇒ **1:1**）。
      · 目标 B「**紧致**」：驻留量 ≈ **单层瞬时**（≈13.5 MiB/层），而非 48 层激活集之并。
        ⇒ **未达成**，需新增「层尾驱逐」（本轮 §8.2）。
      §7B-结果 §1 旧措辞「R_l 记账只驱逐 R_l\A_l」**易被误读为"驱逐不干净"**——已更正为：
      `R_l` 在选路后即 `:= A_l`；**没有驱逐残留**，1.38 GiB 是 48 层激活集的**并**。
  (b) 因果链纠正：**压 `pages_sum` 压不到时间**。二者是**不同的量**——`pages_sum` 量 madvise
      覆盖（含本 token 不访问的页），`minflt` 量真实重驻：
        L0 8.04M vs 95k（84.5×）；A1 1.63M vs 87k（18.7×）。
      差距收窄 **4.5 倍**，板端时间只从 −0% 走到 **−8.6%** ⇒ **过取的页本来就不产生缺页**。
      **任何形如「消除过取 ⇒ minflt/pages_sum 收窄 ⇒ 时间改善」的推理，禁止写入判据。**
  (c) 「消除过取」的边界：gate/up 侧**已做完**（0% 过取）；down 侧**原理上做不到**
      （单专家列带 1728 B < 4 KiB 页 ⇒ 页被邻专家共享，设计稿 §3.4），除非重排文件（D3，另立项）。
      **不得把 down 的专家级驱逐列为优化项。**
  (d) 板端时间上限（算界，非判据）：decode 1140 ms/token，而全部 madvise 覆盖按 33.8 ns/页
      也仅 **272 ms（24%）** ⇒ 板端 decode 主项**不在** madvise 覆盖里；要动板端时间须动**权重字节**。

8.1 动机（**本实验不为转正**）
  目标 B 属**内存轴**。本实验只回答「把 decode 期驻留从 48 层激活集压到单层瞬时，代价多少」。

8.2 实现（默认关）

    (2) **全部差异都在 `rss_file`（mmap 权重页）**。L0 的 file **全程平**（prefill→t=64 只 +1.9 MB）。
    (3) **EVL 的生效量可精确核对**：file(A1) − file(A1E) = 1,354,448 − 714,056 = **640,392 kB = 625.4 MiB**，
        预测应移除 648 MiB ⇒ **96.5%**（与 n=32 时按总 rss 算出的 96.8% 一致）。
    (4) **残留 = `rss_file` 的 SA 专属增量 +207.5 MiB = 门槛（0.1 GiB = 107.4 MiB）的 2.03×**
        ⇒ P-E-1 的 FAIL 完全由它造成；**与 EVL 机制本身无关**。
    (5) 残留的增长形态：A1E 的 file 超量在 t=8/32/64 = 110.5 / 189.8 / 212.4 MiB；
        分段增量 79.3 MiB（t=8→32）/ 22.6 MiB（t=32→64）⇒ **减速收敛于 ≈215 MiB**，
        但尾部仍有 ≈0.94 MiB/token（**未完全平**，n=64 不足以下"已收敛"的结论）。
    ⇒ 归因收敛到**类别**：**"每层激活集之并"之外，还存在一块 SA 专属的 mmap 权重页残留**，
      量级 ≈208 MiB（板端 ctx=256）。**仍待定位到具体张量/段**（下述候选未验证）：
      (a) **边界层**：`evict_l = layer − keep` 永不覆盖 `layer = nl−1`，故第 47 层的
          `down`（108 MiB）+ `A_47`（13.5 MiB）在**任何臂**都不会被驱逐（L0 同理，故这一项应在
          L0 的 file 里已体现 ⇒ 若如此则它**不是** A1E 超量的来源，需实测确认）；
      (b) **readahead 外溢**：SA 每层发 8×2 个 216 页的小区间 WILLNEED（L0 每段 1 次大区间），
          内核预读可能越出被驱逐区间 ⇒ 永不被 expert-granular DONTNEED 回收。
    ⇒ 一步到位的判别实验（**下轮，须另立预注册**）：把逐层驱逐的区间按 **4 KiB 页对齐后向外扩 N 页**
      （N=1/4/16），若残留随 N 下降 ⇒ (b) 成立；若不变 ⇒ (a) 成立。

    **本轮最终结论**：目标 B 的**机制**按设计生效（96.5%，实测 625/648 MiB），但
      **判据 P-E-1 不达标**（残留 ≈208 MiB，2.03× 门槛），且残留的**类别已定位**（mmap 权重页，
      非 anon/KV）、**具体来源未定位**（候选 a/b 待判别）。P-E-2 达标（n=32 1.047、n=64 1.040 两次复现）。
      **形态 A 的转正状态不变（仍不转正，理由仍是 §7B 的 P-A-1t FAIL）。**

  【过程记录（须与本节同引）】
    · 诊断轮的 build 出现 `cp: cannot create regular file './vllm_kestrel': Text file busy`
      —— 仓库根副本**未能**同步，`build-rk3588/` 是新 binary 而根目录是旧 binary。
      **这正是 §4 第 3 条禁止的陷阱**；已按 hash 核对发现并 `cp -f` 修正（两侧同为 `90614b2e…` 后才开跑）。
      ⇒ 以后再遇到 `Text file busy`：先 `pkill -x vllm_kestrel` + `sleep 3`，再 `cp -f`，再核 hash。

  **结论（本 § 范围）**：目标 B「紧致」**机制达成、判据未达成**——
    EVL 把「48 层激活集之并」压掉（96.8%，实测 627/648 MiB），但暴露出的 ≈190 MB 饱和项
    使 `rss_end` 仍高于 `rss_end(L0)+0.1 GiB`；时间代价 +4.7%（P-E-2 勉强过）。
    **形态 A 的转正状态不变（仍不转正，理由仍是 §7B 的 P-A-1t FAIL）。**

9.3 板端「缺页主导」模型（**2 参数拟合 4 点，仅作诊断，不得当定律引用**）
    decode ≈ `786 ms + 4.2 µs × (minflt/token) × (1 − ≈6% 若为专家粒度调用)`

    | A2 | 10,793 | 786（基准点） | 786 |
